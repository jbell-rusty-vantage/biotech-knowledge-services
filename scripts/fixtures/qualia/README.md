# Qualia native evidence fixture

This bounded helper closes the partial-schema construction gap for Deep Agents StageGraph experiments. It does not implement the still-unsupported Mission Control Biotech native-intent mapper or qualify W1/W2.

`partial-schema.json` selects actual pinned v2.2.0 labels and proposal kinds. It is neither a schema migration nor evidence that remote Aura has that release installed. `native-intent.ts` forms `biotech-knowledge-intent.v2` from actual retained source text, captured selectors, source-backed subject fields, authored proposals and an actual frozen KS report revision. `basis.creationOnly` avoids a separate graph preflight; the trusted native planner still checks identity and graph invariants. Required public Person provenance is explicit. The helper performs no deletion, schema install or automatic promotion.

`schema-template.json` is an explicitly nonexecutable placeholder guide for Organization, public Person, Brand, Product, ProductVariant, Package, immutable LabelVersion, IngredientMaterial and ChemicalSubstance. It includes correctly directed structural/asserted edge shapes for product state, ingredient declarations, branding, corporate ownership and public roles. It contains no Qualia facts. Replace every placeholder with actual captured values, choose only evidenced enum variants, remove unproven optional relations and provide captured `subjectEvidence` for every new subject. Copy the product/variant/package/label branch for a second product. Do not infer a legal corporation from a brand, a chemical salt from an ingredient name, a dose from a serving name, or an ownership relation from a product page.

The native report has one explicit primary Claim, preserving the production binding's exactly-one-Report rule. Supply `reportProjection: {primaryAssertionId, claims: [{assertionId, claimRef, claimType}]}` covering every actual frozen KS assertion exactly once. Read those IDs, propositions, qualifiers and judgments from the host's frozen-report result; never reconstruct them from an agent summary. `claimRef` is an agent-local reference. Choose `claimType` from the actual pinned enum, available in `native-vocabulary.json` at `/nodes/Claim/properties/claimType/enumValues`. Do not declare those generated Claims again in `subjects`.

The host creates each Claim from its exact frozen proposition, and a PROPOSED VETTING Assessment from each actual KS support observation. The Assessment records the observation's immutable ID/digest, actual outcome, rationale, method, target support set, qualifier digest and exact assertion qualifiers. It leaves the BKS semantic verdict and disposition unset; `conclusionCode` preserves the KS verdict string verbatim. Full evaluator/raw-response/usage custody remains in KS under the recorded observation ID and digest. An observation projection exceeding the native rationale quota refuses instead of truncating. These records do not promote clinical certainty, world truth, claim lifecycle or accepted assessment status.

Each Assessment links only the exact fragments used by its own KS observation, with `CONTEXT` provenance. Declared support fragments and judge-observed context remain separate; their union is retained for the frozen report. The rationale's `evidenceProvenance.fragments` is an ordered fragment-ID dictionary; `declared`, `observed` and `observation.evidence` contain indices into that dictionary. This preserves their distinct provenance without copying full identities repeatedly. Unknown, altered, missing or duplicated judgment evidence refuses. The original KS outcome, including cited and contradicting full references, remains unchanged. A fragment used by another observation never becomes support for this one merely because it appears in the same report.

The one EVIDENCE_REPORT assesses the selected primary Claim and cites all those native Assessments. Other frozen claims remain explicit cited context. Its name states the primary focus; its body, ledger, structured-body digests and revision references still identify the same complete immutable KS bundle. It is not a newly authored report body or a generic aggregate Claim. Native graph facts use their actual registered predicates and domain structures; copying a proposition onto an unrelated predicate is forbidden. Products, compounds, actors and captured state remain agent-authored subjects/proposals, linked to the actual ingestion Activity through the run's declared `about` lineage.

Include all frozen evidence snapshot IDs in the native captures. The host supplies `captureId`, retained bytes, custody and timestamps. The builder derives unique exact support locators from trusted frozen fragments and those bytes; agents only need to author extra locators for their domain subject/property/proposal evidence. Fixture capture selectors are omitted from canonical native sources. A capture or quote mismatch refuses.

The live host calls `validatedBuildQualiaIntent` before exact-use finalization. This runs the real pinned native compiler against an empty graph, requiring an applicable/noop plan and every subject/proposal applicable. Rejected or held subjects/proposals return `QUALIA_OFFLINE_PLAN_REFUSED` with the actual compiler reasons. Its `offlinePlanCheck` explicitly reports zero graph queries and `admitted:false`; this is a bounded creation-only structural check, not a graph lookup, use decision, admission or ingestion proof. The real writer still plans and validates against Aura at consume time.

`native-vocabulary.json` is generated navigation over the byte-verified pinned release. It exposes real node properties/enums, registered predicate subject/object/literal/qualifier constraints and relationship triples. Use RFC6901 pointers such as `/nodes/LabelVersion`, `/nodes/StudyResult`, `/predicates/LEGAL_NAME` or `/relationships/DECLARES_COMPONENT`; paginate rather than invent missing schema. Regenerate with `node node_modules/tsx/dist/cli.mjs scripts/fixtures/qualia/generate-vocabulary.ts`; append `--check` for a read-only freshness check. The release remains the schema authority, and this file contains no Qualia facts.

Use the companion real KS host at `platform/knowledge-services/apps/verification-executor/src/knowledge-operation/tests/qualia-fixture-host.ts` from the KS owner. It uses a disposable loopback PostgreSQL component and actual K01 HTTP operations. Configuration is `{origin,keyPath,evidenceRoot,bksRoot?}`; `origin` must be Biotech with a UUID installation ID. `keyPath` must be a fresh private local file. Startup prints a JSON `ready` with the URL, issuer, audience and actual separate producer/judge/auditor origins. The host preserves its local database and ignored receipt log for recovery.

IPC accepts one JSON request and returns one JSON response per line:

- `capture`: `{action:"capture",sourceUrl,text,title?,completeness?}` retains actual UTF-8 bytes and returns their custody reference.
- `prepare_report`: `{action:"prepare_report",input:{id,title,summary,claims:[{id,statement,sourceUrl,quote,qualifiers?}],limitations:[]}}` validates exact quotes against host-held captures and returns a full scientific source-report registration. Unknown qualifiers remain null. This builder uses internal attributed research reference, never clinical recommendations or a body-of-evidence certainty rating.
- `call`: `{action:"call",request:{actor,operation,nativeContract,payload,requestId,upstream?,effectKey?,boundEffectDigest?}}` executes the existing authenticated K01 HTTP surface, polls actual handles, reads custody result bytes and verifies their digest. Actors are producer/judge/auditor. Native contracts include research-report/v2, evaluation-context-read/v1, report-observation/v1, report-seal/v1, report-use/v1, decision-resolve/v1 and biotech-knowledge-apply/v1.
- `frozen`: `{action:"frozen",report:<actual report ref>}` returns the stored frozen revision's fields required by `buildQualiaIntent`.
- `context`: diagnostic stored run context for the trusted host only. Do not pass this to the auditor: serve its isolated `evaluation-context-read` instead.
- `consume`: explicit trusted-host dispatch request `{action:"consume",effectKey,authorization:"owner-authorized-qualia-biotech-8032ec07"}`. The host requires the canonical BKS root and actual scoped graph credentials in its process environment. It verifies `BKS_BIOTECH_GRAPH_URI` is exactly the authorized Aura URI, then uses the existing BKS consumer, saves the actual receipt and reads back only that effect's declared IDs. No bootstrap, destructive preparation or graph enumeration occurs.
- `stop`: closes services and preserves evidence/database.

Actual isolated GPT-6.1 Sol/Terra invocations must supply observations and the auditor discovery census. The helper does not generate accepting judgments. A native exact-use held/rejected/review-pending decision stops dispatch. Same-vendor native KS authority is distinct from MC's cross-vendor assessment qualification, and all fixture results continue to say `qualified:false`.

Live acquisition must retain actual tool bytes and truthful hash basis/completeness.
