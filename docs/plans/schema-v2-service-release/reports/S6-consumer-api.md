## What was built

1. **Server repairs.** No v1 SDL fallback; no startup DDL path (`GRAPHQL_ENSURE_OPERATIONS=true`, `GRAPHQL_ALLOW_MUTATIONS=true`, `GRAPHQL_ENABLE_VECTOR=true`, `GRAPHQL_READINESS_RELEASE_CHECK=skip` refuse production start). `/healthz` liveness (no DB); `/readyz` = connectivity + latest `:KsReleaseMarker` vs `projection/compatibility.json` (`$PINNED`) plus the parent release that the pinned `release/compatibility.json` declares read-compatible (v2.0.0, same schemaDigest) + every required edition-applicable `ddl/ddl.json` entry and `required-indexes.json` requirement ONLINE + plan warm-up done; `/schema.graphql` returns the printed executable with `x-bks-*` identity headers; `/identity` reports all digests, library versions, limits, release capabilities. One long-lived driver, explicit database, pool 20, acquisition 2 s, connect 3 s, retry 1 s, reader credentials preferred.
2. **Projection** (`projection/manifest.json`, applied by the single builder): all five `excludeDeprecatedFields` flags (names confirmed in installed 7.6.3 `types/index.d.ts`); `@mutation(operations: [])` forced on every node (zero Mutation root); `@limit(default 25, max 100)` on every node and interface; union roots and the Subjectable root disabled, Entity connection root disabled; `@vector`/`@fulltext` stripped, no vector feature or OpenAI wiring anywhere; omitted: `CaptureAttempt`, `*.lastWriterRunId`, Activity run bookkeeping (runId, missionId, activationId, operationIds, intent/plan digests, receiptIds, externalRunSystem), `SourceSnapshot.storageUri`, `Report.bodyUri`; OD-17 private/contact field patterns (none present in v2; synthetic test proves stripping); MD-D10-06: `publisherUid` projected only with its three stamps (conditional rule; stamps present in v2.0.1, so retained); `Subjectable.privacyClass` exposed on the interface for visibility predicates; visibility `@authorization(filter)` rules on every node (PUBLIC always, INTERNAL only with verified `internal` claim; null privacyClass hidden); 1,111 scalar filter cuts and 1,061 sort cuts derived from the operation inventory and recorded per type in the manifest.
3. **Safelist.** `operations/operations.json`: 9 operations, ids `sha256:<hex>` of the codegen-normalized document (proven byte-identical to the client's persisted documents), variable bounds/defaults, server-bound variables (`actor.visibility`), cost class + static cost, release compatibility. Product profile accepts only registry ids (documentId or APQ hash or exact registered text); unknown ids 404, free text 400, caller-supplied bound variables 400; APQ registration disabled. Engineering profile (`GRAPHQL_PROFILE=engineering` + `x-bks-engineering-key`) allows free queries, still admission-bounded and read-only.
   - Covered views: EntityCard, ProductCard (entity card); ProductVariantsPage (paginated relationship); AssertionEvidenceTrace (HAS_EVIDENCE -> SourceLocator -> SourceSnapshot -> Source, paged); ProductLabelHistory + PackageLabelHistoryPage (Product -> LabelVersion episodes); ClaimView, ReportView (claim/report); ResolveIdentifier (identifier resolution).
   - Excluded with reason (catalog `excluded`): **SubjectAssertionsPage** (assertions about a subject). 7.6.3 anchors `assertionsConnection(where: {subject: {some: ...}})` on a full `:Assertion` label scan with 56 OR-ed EXISTS subqueries: 18 s warm on 60,000 assertions; `typename` narrowing inside relationship filters is rejected by the library ("Attribute typename not found").
4. **Bounds** (`src/limits.ts`, Apollo `didResolveOperation`): coerced variables with defaults; aliases and fragments summed; depth 8 (validation rule and admission); root page 100 / nested 25; union-target lists require explicit `limit` <= 25 (7.6.3 emits no LIMIT otherwise: verified in generated Cypher), union connections rejected (they collect all edges before paging); every connection charged a fanout surcharge, `totalCount` a count cost; relationship predicates in filters charged; `offset` and decoded `after` cursors <= 1000; filter nesting <= 8, input lists <= 50; aggregates rejected; per-cost-class ceilings; request 256 KiB (413), response 2 MiB (`RESPONSE_TOO_LARGE`), DB timeout 5 s (`BKS_TIMEOUT`), end-to-end deadline 8 s (504), DB unavailability mapped separately (`BKS_UNAVAILABLE`). Env vars may only tighten bounds.
5. **BFF** (`apps/product-bff`, Hono): verifies the Supabase session via JWKS (`SUPABASE_JWKS_URL`; issuer/audience/algorithms configurable; role `authenticated`), entitlements only from `app_metadata.bks_entitlements` (`biotech:internal` widens visibility), keeps the service key server-side, forwards only client-safelisted ids with a <= 120 s EdDSA actor context (`typ bks-actor+jwt`, `ctx bks-actor-context.v1`, `vis`, `ent`, `jti`); rejects caller identity headers. GraphQL verifies issuer/audience/signature/type/lifetime/claims with jose before execution and passes only the verified payload as `context.jwt` (the library's pre-verified path; `context.token` is never passed and library token decoding is given an unusable random key). No product app exists in the workspace, so this is the reference BFF.
6. **Client** (`packages/graphql-client`): codegen client preset from `apps/graphql-api/generated/schema.graphql` (printed executable) and the safelisted documents; `documentMode: string`, `replaceDocumentWithHash` (no document text in the bundle), strict scalars (DateTime/Date as wire strings), enums as types; `compatibility.ts` (releaseId, digests, operation ids; generation fails if any codegen hash differs from the server registry); runtime core with injected transport, credential supplier, abort + deadline, typed `TransportError`/`AuthError`/`ValidationError`/`PartialDataError`/`DomainError`/`CompatibilityError`, bounded retry (<= 3 attempts, network/502/503/504 only); ESM + d.ts; compiled with DOM-only libs and `types: []`.
7. **Plan warm-up** (added from measurement): interface-target operations generate 30-82 KB Cypher with 56-69 UNION branches; cold planning measured 2.7-9.2 s (above the 5 s limit). The app executes every safelisted document once (both cursor shapes) after start; `/readyz` stays false until done.

## Query-plan findings (`benchmarks/2026-10-12-plans.json`)

- Every safelisted root starts with one index seek (EntityCard: 68 seeks, one per label branch); no label/all-node scans, no Cartesian products in any shipped operation. DB hits: 41 (ProductCard) to 18,841 (ProductLabelHistory hub); max operator rows 827.
- All connections collect the full relationship fanout before applying `first`/`after` (offset cursors, not keyset). Cost is bounded by fanout, so admission charges a fanout surcharge and offsets are capped at 1000.
- Interface-target connections (`identifiesConnection`, `subject`/`object`/`assertedBy`, `about`) expand into 56-69 UNION branches: generated statements of 30-82 KB, cold planning 1.5-4.7 s in PROFILE and up to 9 s at first execution; warm runs cheap. Mitigated by the startup warm-up. A smaller statement needs a schema change (fewer Subjectable implementers per edge or typed fields), not an index.
- ResolveIdentifier: with a root `sort: uid` + LIMIT the planner may order by the uid index and filter (scheme, value); the root sort was removed so `identifier_scheme_value` is used.
- Relationship-filter predicates do not get `@authorization` filters in 7.6.3 (verified: a filter on an INTERNAL subject returned the PUBLIC assertion). The registry lint requires `privacyClass: { in: $actorVisibility }` (server-bound) inside every relationship predicate of a safelisted document.

## Limitations

- No product application exists; the BFF is a reference bound to Supabase JWKS. Entitlement source (`app_metadata.bks_entitlements`) and claim names are a proposal for the product owner.
- Visibility is privacyClass-based (PUBLIC/INTERNAL; null hidden); no per-record ACLs. Relationship predicates rely on the registry lint plus server-bound visibility, because the library does not apply authorization inside them; the engineering profile sees PUBLIC and INTERNAL.
- Cursor pagination is offset-based (library behavior); deep pages cost the full fanout.
- Benchmarks ran on a shared Windows host with many Neo4j containers; the final disposable graph is quarter-scale (90,201 nodes) and memory-capped (768 MB heap, 384 MB page cache) after the full-scale container was OOM-killed.
- Fly resources unchanged (4 GB); no downsizing (no soak evidence).
