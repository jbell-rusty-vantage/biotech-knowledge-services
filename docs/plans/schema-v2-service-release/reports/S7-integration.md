## 6. Unrun checks and limitations

**Unrun:**
- Gate E and the integration test under Docker (`bks-neo4j-s7`), because the engine was down.
- The Enterprise edition: a role-separated reader for the eligibility route was not exercised.

- MCP surfaces for admission: none by design.
- `pnpm workspace:verify`: not my area.
- Full Mission Control and Knowledge Services suites: not run, per the brief.

**Limitations:**
- **Revocation is not atomic.** The guarantee is authorization at issuance plus a bounded lease (≤60 s). An in-flight witness can commit until its revocation reaches the fence; this is proven in integration row `revocation-after-witness-undelivered`. The fence is generation-coarse: any delivered revocation invalidates all older outstanding witnesses, which must then be re-requested.
- **Single-host ledger.** The admission ledger file backend serializes one host (lock directory plus fsync). Multi-host needs a database-backed ledger, for example a Mission Control PostgreSQL outbox.
- **Local effect ledger.** The Mission Control effect ledger is a local JSONL backend. Production should implement `EffectLedger` over the app's PostgreSQL scoped effect ledger.
- **Cancellation.** The HTTP apply has no native cancellation. The adapter stops new work and then reconciles; this is reported as `nativeCancellation: unsupported`.
- **Serving eligibility.** `NOT_ADMITTED` is returned for effects admitted outside this admission authority, including dev `/kg/admit` effects. Fail-closed is intended.
- **`knowledge.query`** is a byte passthrough to `POST /kg/read`. The executor still decodes v1 bodies unless `BKS_DISABLE_READ_V1=1`. `/describe` `consistency.readModes` reports `["observed"]` (S3's value); S4's read capability advertises `stable_revision` in its details.

## 10. Interface deltas (for INTERFACES revision v3)

1. **New contracts:** `mc.knowledge_request.v1` and `mc.knowledge_delivery.v1` (section 3). Delivery mapping (applies to biotech-knowledge-receipt.v2):

   | Receipt outcome | Delivery state |
   | --- | --- |
   | applied / partial / noop / duplicate | applied |
   | rejected | rejected |
   | failed with `BKS_WITNESS_EXPIRED`, `BKS_TIMEOUT`, `BKS_AUTHORITY_UNAVAILABLE` or `BKS_EFFECT_PENDING` | pending |
   | other failed | rejected |
   | unresolved | unresolved |

   A missing receipt is never "no write".
2. **New executor routes:**
   - `POST /kg/admission/witness` (writer)
   - `POST /kg/admission/revocations`, `/deliver`, `/reconcile` (admin)
   - `GET /kg/eligibility?effectKey=` (reader; 503 when an authority is unavailable)
   - `GET /capability` (reader)

   New `/describe` capabilities, present only when configured: `admission.witness`, `admission.revocation`, `serving.eligibility`. `capability.descriptor` is always present.
3. **Admission inputs:** a witness request carries `grantRef` and an optional `lifetimeSeconds` (1–60). The witness `decisionVersion` comes from the grant authority. A ledger generation that moves during admission refuses issuance with `BKS_WITNESS_REVOKED`.
4. **All-held plans (observed native behaviour).** The planner reports a plan whose proposals are all `held` (no errors) as `outcome: "rejected"`. The adapter treats it as held (`pending`), not rejected. Consider a distinct `held` plan outcome in a later plan contract version.
5. **Catalog descriptor:** `belllabs.knowledge-capability.v1`. The Mission Control binding pins `descriptorDigest`, release, executor version and contracts, and treats any live `/describe` drift as `unsupported`.
6. **Invalidated artifacts:** none. All changes are additive. Applying P2 changes `/describe` contracts, so the descriptor and Mission Control fixture must be regenerated (`node apps/executor/scripts/capability.mjs write`, then copy to `tests/integration/biotech/knowledge/fixtures/`).
