## Conflicts

**OQ-D1-01 — CONFLICT: quantity-bearing asserted edges vs the kernel's four edge-property types.** The kernel pattern says every domain relationship uses one of AssertedEdgeProperties / StateEpisodeProperties / DerivedEdgeProperties / StructuralEdgeProperties; none carries a quantity. D1's `MATERIAL_CONTAINS` needs quantity, comparator, unit, basis and statement kind on the edge (CQ-ID-03, Q-D1-11, Q-D1-13, Q-D1-20 filter on them), so D1 declares `ContentEdgeProperties` = the eleven AssertedEdgeProperties fields verbatim + 8 content fields. D6 (`DECLARES_COMPONENT` amounts), D3 (`ADMINISTERS` dose) and D12 (food composition) need the same. Options: (a) accept domain property types that embed AssertedEdgeProperties verbatim (this packet); (b) one kernel `QuantifiedEdgeProperties` (asserted episode + quantity, quantityLow/High, comparator, unitCode, massBasis) shared by D1/D3/D6/D12, with domain-specific qualifiers on the Assertion; (c) no quantities on edges — values only on the Assertion (`valueNumber`, `unitCode`, qualifiers). Evidence: measured cost here (+13.2 KB, +6 inputs for one type; option (c) saves exactly that) and whether D6/D3/D12 questions filter amounts in GraphQL rather than Cypher. · Owner: **kernel** (A1) with D3, D6, D12; owner decides.

  **Resolved in the kernel model stage (check-stage reading, 2026-10-08):** A1 accepted option (a) as rule M11 — a domain-local edge-property type is allowed when it lists every field of one kernel base type verbatim first, then only filterable qualifiers (K `09-reasoning.md` "Edge-property types"). `ContentEdgeProperties` already complies (the eleven AssertedEdgeProperties fields in kernel order, then 8 qualifiers). Remaining for the owner: only whether the shared-shape option (b) is still wanted once D3 (dose on the InterventionComponent node), D6 (`ComponentLineProperties`, structural) and D12 (amounts on the Assertion) have each chosen differently — see OQ-D1-22.

**OQ-D1-18 — recorded-only asserted edges carry unused valid-time fields.** Four D1 edges (HAS_ACTIVE_MOIETY, COUNTS_TOWARD_NUTRIENT, REALIZES_SUBSTANCE, DERIVED_FROM_TAXON) are asserted but valid time is never stated or read (directive rule 9: episodes only where needed). The kernel offers no asserted type without valid fields, so they carry `AssertedEdgeProperties` with null bounds and basis UNKNOWN. A lighter `AssertedRecordedEdgeProperties` (relationshipUid, assertionUid, recordedFrom/To, lastWriterRunId) would make the decision visible in the schema. Evidence: per-type byte cost of the 6 omitted fields (expected small) vs the clarity gain. · Owner: **kernel**.

  **Resolved (check stage):** the kernel added `AssertedRecordedProperties` (M10, exactly these five fields). The four recorded-only D1 edges now use it in `04`, `05` and the fixtures; measured effect in `09-reasoning.md` ("Executable measurement").

**OQ-D1-20 — CONFLICT (minor): node-register `mutations` field vs kernel L2.** The contract asks `mutations (create/update/delete allowed)` per node type; the kernel pattern sets `@mutation(operations: [])` on every type (the executor is the only writer). D1 records `{create: false, update: false, delete: false}` with a note that the executor writes. · Owner: **owner** (A1 question 1 already asks to adopt L2 program-wide).

**OQ-D1-21 — tooling: `print-schema` silently falls back to the pinned SDL.** `apps/graphql-api/src/server.ts loadPinnedSdl()` tries `BKS_SCHEMA_PATH` and, if that file does not exist, uses the pinned 55 MB schema without a warning; a typo in the path produced a "successful" 57,908,217-char print during this stage. Every agent measuring module cost can be misled. Fix: fail when `BKS_SCHEMA_PATH` is set but missing, or print the resolved path. · Owner: **owner** (apps/graphql-api; not editable by domain agents).
