## What needs custom tooling

1. **Label-string resolver with a salt/form check** (Q-D1-26): DSLD row + form UNII → GSRS record → ACTIVE MOIETY; never a PubChem name→CID hit alone. Inputs: tool:dsld-api, tool:gsrs-api; output: RESOLUTION assessments.
2. **Rule table + projection job** for `rule:mw-ratio.v1`, `rule:nutrient-equivalent.v1`, `rule:daily-max.v1` (and the two used here only as fixture rules: `rule:threshold-compare.v1`, `rule:extract-ratio-dhe.v1`) reading MOLECULAR_WEIGHT FIELD assertions pinned to a GSRS record version.
3. **LNHPD local index** (licence ↔ lnhpd_id ↔ NPN ↔ ingredient rows) refreshed from the bulk dump, because the licence endpoint cannot be filtered.
4. **Deposit parser** for NCBI synonyms → CULTURE_COLLECTION identifiers (ATCC, LMG, DSM, …), and a taxonomy-history reader that turns authority strings plus a publication date into PARENT_TAXON episodes.
5. **Locator builder** (as in F11) that refuses ambiguous quotes, records code-point offsets with prefix/suffix, and re-selects on every new capture; JSON locators should pin a pointer, not a first match.
6. **Intent contract extension** request (kernel/executor): a proposal kind for an Assertion with an object node but no typed edge (predicate-only relations such as MARKETED_UNDER_MARK, SUPPLIES_MATERIAL) and for CALCULATED assertions with DERIVED_FROM inputs (recorded in 11-open-questions.md, OQ-D1-25).
