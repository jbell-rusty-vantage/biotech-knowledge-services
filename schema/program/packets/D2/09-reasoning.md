The model in one paragraph: a mechanism finding is a **kernel Assertion** (subject = compound or intervention, object = Mechanism, MolecularEntity or D1 metabolite, predicate from a closed D2 list, `basisKind` from the kernel) that points at **one MechanismEvidenceContext** (organism, compartment, setting; exposure only for unregistered groups, otherwise D3's InterventionComponent). Mechanisms form a curated vocabulary (hallmarks, processes, pathway records, molecular functions) with an **asserted** reference hierarchy and asserted participants (one Assertion per authority record and release). The only compound → mechanism edge is a **read-only projection** over those Assertions with a method version and summary properties (direction, best basis, highest setting, human-measured). Mechanism → outcome links are Assertions read at query time (and D10 Association records for computed scores). Species and anatomy are enums plus ontology ids. Everything else stays an `Assertion.predicate`.

### Derived projection method spec (brief deliverable)

**`d2.affects-mechanism/v1`** — writes `(m)-[:AFFECTS_MECHANISM]->(t)` for modulator m ∈ {ChemicalSubstance, Intervention} and target t ∈ {Mechanism}.

1. Inputs: current Assertions (`recordedTo IS NULL`) with `status IN [ACCEPTED, DISPUTED]`, `predicate IN $mechPredicates` (03 shared fragments), and subject a ChemicalSubstance or Intervention. IngredientMaterial subjects roll up through D1 REALIZES_SUBSTANCE / HAS_ACTIVE_MOIETY, and Product claim subjects through the D6 label path (Package → LabelVersion → DECLARES_COMPONENT → material → substance). Never inputs: MENTIONS, GDS output, the authorizing Assertions of reference edges, REJECTED/UNRESOLVED/PROPOSED Assertions.
2. Object resolution: a Mechanism object → itself. A MolecularEntity object → every Mechanism it PARTICIPATES_IN (current episode, `recordedTo IS NULL`) with `viaParticipant: true` (adversarial review: no MolecularEntity edge is written any more). A D1 metabolite object → every Mechanism it PARTICIPATES_IN (`viaParticipant: true`).
3. Sign per input: INCREASES_* and ACTIVATES → +; DECREASES_*, INHIBITS and ATTENUATES_INDUCTION_OF → −; NO_CHANGE_IN → 0; MIXED_EFFECT_ON → ±; BINDS → none. Polarity NEGATIVE turns a directional input into 0 (a denial, kept at its own basis). Through a participant whose `participantRole` is NEGATIVE_REGULATOR, the sign flips.
4. `direction`: computed from DIRECT_MEASUREMENT inputs when any exist, else from all inputs. One sign → INCREASES / DECREASES / NO_CHANGE. Disagreeing signs → MIXED. Only BINDS → null.
5. `bestBasis`: the first match in DIRECT_MEASUREMENT > INFERRED_FROM_MEASUREMENT > CALCULATED > CITED_FROM_PRIOR_WORK > EXPERT_OPINION > PERSONAL_EXPERIENCE (= THIRD_PARTY_ANECDOTE) > MANUFACTURER_CLAIM > HYPOTHESIS (= MECHANISM_REASONING) > UNSTATED (the two values K added in its adversarial review rank as shown until K publishes a kernel-wide order, 11 item 32). `highestSetting`: HUMAN_INTERVENTIONAL > HUMAN_OBSERVATIONAL > IN_VIVO_MAMMAL > IN_VIVO_NONMAMMAL > EX_VIVO > IN_VITRO_CELL > IN_VITRO_CELL_FREE > IN_SILICO, over the contexts of measured inputs. `humanMeasured`: some DIRECT_MEASUREMENT input has a HUMAN context. `nContexts`, `nHumanContexts`, `nNoChangeContexts` count distinct contexts.
6. `score` (method-owned support, never truth): Σ w(setting) over distinct measured contexts whose sign equals `direction`, minus Σ w over contexts with the opposite sign or 0. Weights: human interventional 1.0, human observational 0.8, mammal 0.5, non-mammal / ex vivo 0.3, cell 0.2, cell-free / in silico 0.1. Null when direction is MIXED.
7. Citation and lineage: `derivationRule = 'd2.affects-mechanism/v1'`, `derivedFromAssertionUids` = sorted input uids, `derivedAt`, `lastWriterRunId` = the projection run. The run is a kernel Activity (activityKind PROJECTION, methodVersion = derivationRule, `inputSetDigest`), so "which run computed this association" is answered (00-DIRECTIVE 4.2).
8. Refresh: incremental on every admitted, superseded or re-adjudicated mechanism Assertion (executor event), plus a full nightly rebuild. MERGE key (m, t, derivationRule). An edge whose input set becomes empty is removed, because derived edges are regenerable and history stays in Assertions and Activities (K: allowed).

**Mechanism → outcome (query time, no stored edge).** The retired `d2.influences-outcome/v1` rule survives as the hop-2 reading of Q-D2-14 / Q-D2-26: Assertions whose subject is the Mechanism, or a MolecularEntity / D1 metabolite that participates in it, with `predicate IN $outcomePredicates` and an object Outcome or Condition; MECHANISM_OF and INCREASES_RISK_OF count as +; in a context with `geneticManipulation` LOSS_OF_FUNCTION or KNOCKDOWN the sign flips. Authority association scores (Open Targets) enter as `basisKind: CALCULATED` Assertions; BellLabs computed scores are D10 Associations.

The method was re-run on the fixture data after the adversarial review (`project.py`): 9 AFFECTS_MECHANISM edges, all matching the declared ones; expected outputs are in each fixture's `assertions.yaml`.

## Risks

1. **Projection semantics through participants and protocols.** Sign propagation through `participantRole` is a heuristic: wrong for feedback loops and for metabolite OUTPUT roles (NR → Nicotinate metabolism is MIXED because NAAD rose and NAD+ did not), and one study can split by protocol (AET → mitochondrial respiration is MIXED: SUIT1 trend, ADP-titration increase). Mitigations: `viaParticipant` is exposed, the method is versioned and regenerable, and 11 item 21 lists v2 options.
2. **Mechanism resolution of free text.** Claims say "boosts cellular energy" or "activates longevity genes". Resolving them to a curated Mechanism (vector + fulltext) can go wrong. Mitigation: a kernel RESOLUTION Assessment licenses the object binding, and an unresolved claim keeps `proposition` text and no object.
3. **Seams that moved under D2.** D5 restored D2.Outcome in TargetMeasure (closed, 11 item 27); D10 still claims its Association replaces AFFECTS_MECHANISM, and K's M11 list does not yet name DerivedEdgeProperties (11 item 1, open); D3 must add three enum values for in-vitro and rodent contexts (11 item 30). The synthesizer must re-check names and enum values across packets.
4. **Outcome boundary.** VO2max, grip strength and HRV sit between D2 Outcome (endpoint concept) and D4 Biomarker (physiological signal). D5's TargetMeasure now admits both, so a boundary rule is needed with D4 and D5 to avoid two nodes for one concept (11 item 5).
5. **Context volume.** One context per exposure group × compartment is about 5–20 per paper. That is fine at the target corpus size (10⁴ papers → ~10⁵ contexts), but `contextKey` identity must be deterministic or re-ingestion duplicates contexts.
6. **Licence.** KEGG is academic-use only. If the owner refuses it, reference topology comes from Reactome, GO and WikiPathways only (CC0 / CC BY).

## With twice the budget

In order of value: (1) `MEASURED_WITH_ASSAY` context → D4 AssayVersion, so "which findings used a validated assay" is a traversal. (2) `ORTHOLOG_OF` MolecularEntity → MolecularEntity, for model-organism → human transfer at gene level (Q-D2-20, CQ-MX-03). (3) A `GeneticVariant` node for genotype risk states (APOE ε4) that D4 and D5 would share. (4) A materialized mechanism → outcome edge again, if Q-D2-26 hop 2 proves too slow at corpus scale and D10 Associations do not cover it. (5) A `MechanismChain` node only if source-asserted chains become a vetting unit for evidence missions. Even with twice the budget, D2 would still not bring back Species or AnatomicalContext nodes: no question traverses through them.
