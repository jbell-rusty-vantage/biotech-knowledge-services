## Notes for D11 (action space)

1. **ClinicalTrials.gov registry history is not agent-reachable on 2026-10-08.** The public v2 API serves only the current version; the site's internal `/api/int` endpoints that power the Record History tab return 403 to every automated client tried (five tools, three proxy modes). Options: (a) BellLabs observes versions itself: poll v2 by `lastUpdatePostDate` and snapshot each change (this is what `RegistrationVersion` "as captured by BellLabs" already means); (b) AACT daily loads (current-only, but archived monthly snapshots exist) — not tested; (c) ask NLM for a history export; (d) human-browser capture for high-value trials.
2. **ISRCTN carries history in prose**: dated Editorial Notes plus "Amended dd/mm/yyyy:" / "Provided at time of registration:" blocks inside the field text. A parser can turn these into `RegistrationVersion` episodes with valid-time = the note date.
3. **CTG `annotationSection.unpostedAnnotation`** exposes results-submission events (RELEASE / RESET) even when results were never posted (NCT02678611). Cheap, agent-ready signal for "results submitted but not posted".
4. **Crossref is now the Retraction Watch carrier**; the `source` field distinguishes `publisher` from `retraction-watch`. Labs API adds reasons but is unstable and has a character-drop defect.
5. **NCBI rate limit**: 3 requests/s without a key; a team of eight agents sharing one IP will hit it. Add `NCBI_API_KEY` to `.env` (10 req/s).
6. Registry records contain personal contact data (CTG `pointOfContact` email and phone for NCT04313634). Ingestion must drop or classify these fields (`privacyClass`), never copy them into fixtures.

## Adversarial-review stage (A4, 2026-10-08)

Polite-pool contact address (finding on provenance): the research-stage rows above record only that a `mailto` parameter was sent to Crossref REST and Crossref Labs (`curl, mailto=`); the address itself was not logged, and its kind (role address or a person's) cannot be established after the fact. The Crossref Labs snapshot the fixture uses (`s-crossref-labs`, sha256 9b5920ea…) is unaffected: an independent reviewer re-fetched it with a neutral role address and got byte-identical bytes. Rule from this stage on: polite pools receive only a role / service address, never a person's, and every log row names the kind used ("mailto: role address"); the project service contact is an owner decision (11-open-questions #32).
