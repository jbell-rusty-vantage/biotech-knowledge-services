## What needs custom tooling (feeds D11 `tooling/action-space.yaml`)

1. **Registry history**: an ISRCTN history-prose parser (dated "Provided at time of registration / Updated as of / Amended" blocks and Editorial Notes → RECONSTRUCTED RegistrationVersions with valid time from the stated date) and a CTG version observer (poll v2 by `lastUpdatePostDate`, snapshot each change, emit OBSERVED versions), because CTG history is blocked.
2. **Results extraction**: CTG `resultsSection` → one JSON pointer per reported number (estimate, bounds, n, P, AE affected / at risk), with group ids mapped to arms; paper text → one TEXT_QUOTE per number inside a verified sentence.
3. **Text normalizer and verifier**: a versioned `xml-textcontent/v1` normalizer shared by locator writer and verifier (11-open-questions #29); chunker over `<p>` spans with D9 Chunk fields (`textVersionHash`, `chunkerVersion`).
4. **Revision ingestion**: Crossref `updated-by` / `update-to` + PubMed CommentsCorrections → per-asserter REVISES episodes (revisionKind = kernel SourceRevisionKind) when the notice is identified; status-only flags (OpenAlex `is_retracted`) → kernel `HAS_REVISION_STATUS` on the Source carrying the DOI, never REVISES; Retraction Watch reasons from the CSV rather than Labs. Crossref `is-referenced-by-count` is asserted by Crossref (computed from deposited references), not by the publisher.
5. **Service identity for polite pools** (Crossref, Crossref Labs, OpenAlex) and an `NCBI_API_KEY`.
6. **Intent v1 gap**: predicate-only Assertions with an object node, NEGATIVE edges, held proposals (11-open-questions #30).
