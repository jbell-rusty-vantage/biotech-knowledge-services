## Risks

- **Per-source duplication.** Every arm, population, outcome declaration and result exists once per stating record. Cross-source matching rests on normalized keys (`armKey`, `outcomeKey`) that can split one outcome in two or merge two; Q-D3-01, Q-D3-15 and Q-D3-16 inherit that error. Mitigation: keys produced by a versioned normalizer, curated corrections as superseding Assertions, an EQUIVALENCE Assessment when two keys are claimed equal (11-open-questions #24).
- **ClinicalTrials.gov history is not agent-reachable** (403 to every tool; `_notes/tool-log.md`). HAS_REGISTRATION_VERSION for CTG fills only forward from our first capture until NLM access or a human capture exists; ISRCTN history is reconstructed from prose (scrape-only, readiness 1–2).
- **Edge-property rule (resolved by the kernel's M11 superset rule, check stage).** Both module types now follow it (base fields verbatim first, one filterable qualifier, source wording in `Assertion.qualifiers`). Residual risk: intent v1 `AssertionCore` has no `qualifiers` field, so the fixtures carry the role label and the Retraction Watch reasons in the proposal `rationale` (11-open-questions #30).
- **Target reach for condition-coded outcomes.** D5's `TargetMeasure` (Biomarker | Metric | Outcome) now covers D2 Outcome, so mortality and disability-free survival reach a Target; outcomes resolved to a D2 Condition (incident dementia, hemorrhage, adverse-event terms) still do not (11-open-questions #8, narrowed).
- **Assessment vocabularies must stay registered.** The D3 assessment questions now filter on the kernel's typed slots (`conclusionCode`, `gradeScheme` / `grade` / `certainty`, `facets`) with the vocabularies below; free text in those slots would silently break CQ-EV-04 / CQ-ST-03 / CQ-AX-24. Still untyped: numeric HED bounds of dose translation and the per-input `inputRole` of evidence syntheses (11-open-questions #6).
- **Volume.** Every asserted edge (STATED_IN above all) needs one kernel Assertion (`assertionUid` is mandatory): a 20-outcome trial with 10 registry versions and 3 papers writes hundreds of Assertions. Relationship-property indexes on `assertionUid` are required (03 conventions).
- **Locator alignment for U2E.** JATS quotes are exact over normalized text content, not raw bytes (U+00A0, inline `<italic>`); D9's `COVERS_LOCATOR` span overlap needs locator and chunk offsets in the same normalization (D9 records `normalizationVersion` on Chunk).

- **`nestedOperations: [CONNECT]` on two structural edges** (`RESULT_FOR`, `RESULT_FOR_ARM`; rule 3 asks `[CREATE, CONNECT]` for structural edges): both bind records another structural edge of the same intent already created (`HAS_OUTCOME` creates the OutcomeDefinition, `HAS_ARM` the StudyArm); a nested CREATE from a result would create a second, unattached outcome or arm. Same reasoning as the kernel's exception for structural edges to existing records. With `@mutation(operations: [])` the setting changes no printed input type.
