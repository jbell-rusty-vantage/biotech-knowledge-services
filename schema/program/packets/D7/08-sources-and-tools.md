## What broke

1. **Text projection line endings** — the SEC HTML → text projection written by Python on Windows had CRLF line endings; offsets computed after universal-newline reading did not index the file bytes (29 of 85 locators failed re-selection). Fixed by writing LF and recording the projection digest; the lesson for the capture service: the projection is part of the snapshot (canonicalProjectionHash) and must be platform-independent.
2. **PDF-to-markdown digests are not stable** — the same FTC PDF parsed twice today gave 8,649 and 8,533 bytes (different digests). Snapshot identity for PDFs must be the PDF bytes (which plain HTTP cannot fetch from ftc.gov) or the parser output must be pinned by parser version.
3. **Script-gated disclosure list** — not capturable live without a browser, but captured from the Internet Archive `id_` copy of the pre-redirect URL (/disclosures/, 2025-09-30; adversarial-review correction: the fixtures and check stages had not tried the archive for it, so the Q-D7-20 ceiling was wrongly PARTIAL_EXCERPT for every date). The live 2026 list stays PARTIAL_EXCERPT; the archived list is COMPLETE as of its capture time and scope-limited by its own note.
4. **Intent v1 expressiveness** — predicate-only Assertions with an object node, NEGATIVE-polarity interest denials, claim occurrences and Assessments do not fit the proposal kinds; the fixture intents carry them as `assertion.literal` with the object uid in `valueString`, or omit them with a note.
5. **Name-only persons** — Form D related persons and RePORTER PIs carry no shared identifier with self-published pages; every cross-source person link is a RESOLUTION Assessment.
6. **SEC HTML raw digests do not reproduce** — EDGAR injects a bot-manager script tag with a rotating path at the end of every Archives HTML response, so a RAW_BYTES digest of SEC HTML cannot be re-verified on a later fetch (readiness gap for snapshot identity). Verification identity for SEC HTML: the canonical text projection digest (`canonicalProjectionHash`, which excludes script content) or the raw bytes with the trailing injected tag removed; the fixtures keep the RAW_BYTES `contentHash` (what was fetched) and verify by the projection.

## Custom tooling needed (feeds the D11 action-space registry)

- A capture service that stores raw bytes plus a versioned canonical text projection (HTML visible text, PDF text by page) with both digests, and NBSP/whitespace normalization rules recorded in the selector (TEXT_QUOTE `normalization`).
- An SEC filing parser for beneficial-ownership tables and their footnotes (holder, shares, percent, basis wording "may be deemed", voting/dispositive power, cited 13D/13G and its date) — the investor lens depends on it.
- A role-code legend parser for self-disclosure pages (code → roleKind / stakeKind / valueKind) with the legend span cited on every assertion.
- An intent v1 extension (or v2) for object-bound Assertions without edges, claim occurrences and resolution/assessment proposals.
- An archive-first capture path for disclosure lists: Internet Archive `id_` copy of the pre-redirect URL (gzip-decode, hash, project), then a browser-backed capture only if no archive copy exists, logged as a readiness exception each time it is used.
- A snapshot-identity rule per publisher for injected or rotating content (EDGAR's trailing script tag): verify by projection digest or by a documented strip rule, never by raw bytes alone.
