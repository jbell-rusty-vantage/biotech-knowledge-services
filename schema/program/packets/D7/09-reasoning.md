### Conflict relevance vocabulary (D7-owned subkind values for kernel `Assessment` kind CONFLICT_RELEVANCE)

`assessmentSubkind: D7.conflict-relevance`; `ASSESSES` → the speaker Person and the occurrence's Claim (an Assertion is not Subjectable); `DERIVED_FROM` → the claim occurrence and each interest Assertion considered; `methodVersion` names the rule set. Encoding (check stage, kernel M9 slots; OQ-D7-03 resolved): `conclusionCode` = relevanceLevel {DIRECT, INDIRECT, NOT_RELEVANT, UNDETERMINED}; `facets` = `relevanceBasis=` {SAME_PRODUCT, SAME_BRAND, SAME_ORGANIZATION, SAME_PRODUCT_CATEGORY, SAME_SERVICE_CATEGORY, SAME_SUBJECT_PROMOTED, COMPETITOR, UNRELATED}, `temporalOverlap=` {OVERLAPS, DISJOINT, UNKNOWN} (rule OVERLAP in `03`), `disclosureFinding=` {DISCLOSED_IN_CONTAINER, DISCLOSED_IN_LATER_REVISION, DISCLOSED_ELSEWHERE, INADEQUATE_DISCLOSURE_PER_REGULATOR, NOT_DISCLOSED, NOT_FOUND_IN_PARTIAL_CAPTURE} (rule DISCLOSURE TIMING in `03`). Four values were added in the check stage because the fixtures needed them (SAME_PRODUCT_CATEGORY: Attia/Dexcom; SAME_SUBJECT_PROMOTED and INADEQUATE_DISCLOSURE_PER_REGULATOR: FTC; DISCLOSED_IN_LATER_REVISION: the corrected Attia fixture); the registered list is in `10-seams.yaml`. Other D7 subkinds: `D7.role-agreement` (EVIDENCE_SYNTHESIS; Q-D7-08), `D7.disclosure-coverage` (QUALITY; Q-D7-20, Q-D7-24), `D7.undisclosed-tie-lead` (INSIGHT; Q-D7-23). Disclosure is never a boolean on an edge: it is the existence of an interest Assertion asserted by the holder whose locator sits in the same Source as the occurrence (CQ-CL-05 pattern).

### Privacy rule (the brief's open question, now a model rule)

A Person exists only for a public actor in the role that makes them public (`publicActorBasis`). Stored: name, public role ties, public identifiers (ORCID, SEC CIK, NPI), credentials as printed. Never stored: date of birth (Companies House shows month/year next to officer roles), residence or address, phone/email (NPPES authorized official, CT.gov contacts), family members (proxy footnotes naming trusts and relatives), transaction-level personal payments (Open Payments rows are read at query time only, Q-D7-18). FTC-named endorsers and Form D related persons enter only when a D7 question needs them, preferably with the organization as the assertion subject. `privacyClass` is set on every node (null fails closed). A family or personal relationship is never stored even when a source states it (OQ-D7-09).

## Risks

- **Disclosures and ties are dated by the wrong clock (check stage, sharpened in the adversarial review).** A disclosure on a page is easily dated by the page's own date line; the Attia article (dated 2021-06-20) carries a Dexcom disclosure that its 2021-06-21 archived rendition does not, and the tie itself is dated only by the author's separate list (Sep 2020 – Aug 2021), archived from a URL that now redirects. Two errors follow from reading the current page alone: "disclosed in the same container" (wrong for the original audience) and "currently an advisor" (a stale present-tense title three years after the role ended). Mitigation: rule DISCLOSURE TIMING in `03`, the value DISCLOSED_IN_LATER_REVISION, the snapshot's `publishedAt` as the version date, an archive lookup for the disclosing page and for the disclosure list (the `id_` copy of the pre-redirect URL), and Q-D7-17 for stale titles; cost: one more capture per disclosure and the archive's sparse coverage (OQ-D7-31).
- **Superset edge-property types must track the kernel.** K M11 allows them but rule (5) says a kernel base-type change must be copied into all four D7 types in the same synthesis pass; a missed copy breaks the executor's base-field writes.
- **Observation dates live only on the Assertion** (adversarial review: the edge copy `observedAt` was removed). OVERLAP and the patterns that print an observation date join the authorizing Assertion through `assertionUid` (TRACE already does); a GraphQL client filtering episodes by observation date must filter Assertions instead. Gain: no copy that can drift from its Assertion, four fewer fields.
- **Brand-only sources.** A disclosure that names a brand ("advisor to InsideTracker") must resolve to the holder Organization before an interest edge can be written; if the holder is unknown, the extractor writes an Assertion only (object Brand) and no edge — those ties are invisible to the interest-family patterns until resolved. Measure on fixtures.
- **Group roles.** Roles stated for a group ("EdenRoc Sciences companies F,I,E,A,B, IP") sit on the CORPORATE_GROUP record; questions that need the member company must follow PARENT_OF GROUP_MEMBER_UNSPECIFIED and label the tie INDIRECT. An over-eager extractor that copies the group role to each member breaks the pinned V-434 rule.
- **Manufacturer and supplier roles have no typed edge in any module** (D6, D8 and D1 all keep them predicate-only), so CQ-MF-01 (value 1) is answered from Assertions with no GraphQL filter (OQ-D7-28). Adversarial review: D7, as owner of the Organization anchor, now publishes one name set (MANUFACTURES, CONTRACT_MANUFACTURES_FOR, SUPPLIES_MATERIAL with `exclusivity=`, MANUFACTURER_UNNAMED) and D7's patterns use only these; D6 already writes the Niagen sole-supplier fact as SUPPLIES_MATERIAL exclusivity=SOLE with D7's Organization uids; D1 (MANUFACTURES_MATERIAL), D6 (MANUFACTURER_STATEMENT) and D8 (SUPPLIES_INGREDIENT, EXCLUSIVE_SUPPLIER_OF) are asked to rename.
