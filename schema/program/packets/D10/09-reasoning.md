## Decisions — nodes (alternatives considered)

### DecisionCriterion (kept from W23, reshaped)

- **Chosen:** one node per criterion *version*; a criteria set (ranking method) is the group sharing `criteriaSetKey` + `criteriaSetVersion`; `criterionKind` (SCORE / BLOCK / FILTER / TIEBREAK), `direction`, `weight`, `rule`, `inputPredicates`, `inputAssessmentKinds`, `targetKeys` (D5 vocabulary keys), `publisherUid`, valid time (publisher's method dates) and recorded time + `supersedesUid`. Implements Subjectable so a ranker's method statement ("Penalties are twice as heavy if a product has less than what they claim …", Labdoor) is a kernel Assertion whose subject is the criterion.
- **Why a node:** Q-D10-01 filters criteria by set, version and target; CQ-RC-07 traverses criterion → reports when a criterion is superseded; Q-D10-10 / Q-D10-11 compare two rankers criterion by criterion. The research found that every grader versions its method and edits published rows (Labdoor 2017 rounding rule, USPSTF grade definitions 2007/2012, Open Targets releases) — a criterion without a version is not replayable.
- **Rejected:** (a) a `RankingMethod` / criteria-set node with HAS_CRITERION — one more node and relationship type for a grouping two properties express; promote if a question traverses methods independent of criteria. (b) PolicyVersion DECLARES_CRITERION (pinned) — PolicyVersion is not a node; a comparison may use a subset. (c) Criteria as a JSON property on the Report — not traversable from the criterion side and the Report is a kernel type. (d) BellLabs criteria only — then third-party rankings could not be compared on criteria (Q-D10-11), which is the finding that explains why rankings disagree (U.S. News #1 is magnesium oxide; Examine calls oxide poorly absorbed).

### ReportItem (new; the public part of pinned RecommendationOption)

- **Chosen:** SECTION and ROW items under a kernel Report, insert-only, each citing the subset of inputs its content rests on (DERIVED_FROM), the option it is about (ASSESSES), blocking inputs (BLOCKED_BY), disposition, rank, cell values, missing facts, body offsets, uncited-sentence count.
- **Why a node:** four value-1/2 questions filter or traverse below the report: CQ-RC-06 (BLOCKED rows and their blocker's locator), CQ-RC-01 (rejected options with reason), Q-D10-13 / CQ-AX-11 (which row cites a now-superseded input), CQ-AX-01 / Q-D10-14 (which sections have uncited sentences). ConsumerLab's post-publication row change to "Not Approved" (research FC-10) is the real-world case for row-level citations.
- **Blocking (adversarial-review stage):** a BLOCKED row's `BLOCKED_BY` targets the D5 `UseConstraint` (the shared identity of a scoped use concern that D5 declares for CQ-RC-06) or a harm Assessment; the row cites the resolving Assertion and the triggering fact with DERIVED_FROM. Two reports blocked by the same concern now join on one node, and the population or dose scope lives on the constraint, so a ROW ASSESSES exactly its option.
- **Rejected:** (a) citations only at report level (kernel minimum) with rows in the body — CQ-RC-06 and Q-D10-13 become body parsing. (b) Per-sentence nodes — the kernel keeps sentences in the sealed verification ledger (decision 4); sentence nodes would multiply nodes per report by ~30 and duplicate the ledger; items carry body offsets so ledger sentences resolve to an item. (c) Edge properties `{itemKey, role}` on Report→Assertion — a kernel type cannot gain a D10 property type, and a row with five cited inputs would repeat its disposition and rank five times. (d) Implementing Subjectable — no question makes a row the subject of an assertion; Entity only keeps it out of the subject space.

### Association (revived retired pinned type, as a read-only projection record)

- **Chosen:** one node per (kind, member pair, method version, input digest), two derived `ASSOCIATES` edges to the members (`anchorUid` orients it), `DERIVED_FROM` to inputs up to 5,000, `score` documented as "not a confidence, not evidence", `components` breakdown, statistic + threshold for signals, `computedAt`, `staleAfter`, supersession. Written only by a PROJECTION Activity, and **BellLabs-computed only**: an external score is an Assertion by its producer, never copied into an Association. Implements `Entity` only.
- **Why a node:** directive 3.6 forbids a plain edge with a score between two domain entities; Q-D10-05 returns the per-kind breakdown, method version and inputs of one computed record; CQ-AX-08 audits that record's inputs and digest (withdrawn inputs, method-version mismatch, staleness). A derived edge cannot carry a breakdown, a statistic, an input set or supersession. Sibling projections it can host if their owners materialize them: Q-D2-18, Q-D2-19, Q-D5-19, Q-D7-22, Q-D7-23 (10-seams).
- **Adversarial-review correction:** the fixtures-stage fixture copied Open Targets scores into two "pass-through" Associations and argued from Q-D10-06 that an interpretation Assessment must be *about* an Association, hence Subjectable. Both contradicted rejected option (e) below. The fixture now computes a real BellLabs projection (`bl-assoc/faers-prr@1`: PRR 76.4 for sirolimus / transplant rejection from four openFDA FAERS count Assertions); the external Open Targets LRT stays an Assertion by Open Targets; the SAFETY_SIGNAL interpretation ASSESSES the drug and the event and cites both. No question needs an Assertion or Assessment about an Association record, so `Subjectable` was dropped (promote if an analyst must judge one specific projection record rather than the pair it scores).
- **Rejected:** (a) typed derived edges between domain types (pinned AFFECTS_MECHANISM, INFLUENCES_OUTCOME, ASSOCIATED_WITH_*): each pair of types costs a field and pairs in the owning module, and DerivedEdgeProperties cannot carry components or a statistic. D2 has since cut INFLUENCES_OUTCOME and keeps AFFECTS_MECHANISM as a traversal shortcut with its own `MechanismProjectionProperties` (including `score`), a superset of DerivedEdgeProperties that the kernel's base list does not name. Proposed rule: an association that carries a method score is an Association node; a derived edge may carry filterable summary facets but no method score (11-open-questions #15, #37; owners kernel / D2). (b) A kernel Assessment of kind ASSOCIATION: PLAN 6.1 separates assessments (judgments with a producer who answers for them) from projections (regenerable, method-determined). (c) No stored association, only GDS streams: Q-D10-05's breakdown and CQ-AX-08's audit need a durable record. (d) Two endpoint relationship types (ASSOCIATION_FROM / _TO): the `anchorUid` property does the same for one type and one pair less. (e) External scores (Open Targets, a producer's FAERS statistic, third-party rankings) as Association records: they are captured Assertions by their producer with a locator into the JSON snapshot; BellLabs records are separate so the two never conflate.

## Risks

- **The comparison engine is new code.** Q-D10-01's rule evaluation (BLOCK first, weights, unknown ≠ zero) is application logic behind a read intent (`comparison.compute`); `DecisionCriterion.rule` needs a small expression grammar. Until it exists, rankings are hand-built in fixtures. Owner: D11/executor.
- **ReportItem write path.** `report.publish` (one transaction: Report, items, citations, WAS_GENERATED_BY) does not exist in the executor; the kernel lists report publication as a minimum citation set but no intent kind. Owner: owner/kernel (11-open-questions).
- **Cell values as strings.** `cellValues` encodes criterion uid, value and input uid in one string per cell; cell-level recomputation needs parsing. Accepted because no question traverses criterion → cell; promotion path is SCORED_ON.
- **Association volume.** SIMILARITY with topK 10 over ~100k entities is ~1M Association nodes; bound by restricting similarity to labels a question needs and keeping only the current version (old versions closed, purged by a retention policy outside the graph's "nothing deleted" rule for evidence — owner decision needed, 11-open-questions).
- **Two DERIVED_FROM targets on ReportItem plus Report-level citations** can drift (an item cites what the Report does not). The publish intent must check item citations ⊆ report citations.
- **Kernel enum reads.** D10 patterns filter kernel enums (verdict, effectDirection, reportKind); a kernel rename breaks them silently in Cypher. Mitigated by the kernel's "additive only" rule.

## Answer-kind table — cross-packet pass (2026-10-08, after the adversarial reviews)

**Method.** `_notes/answer_kind_extract.py` reads the first `| id |` table of every packet's `02-questions.md` from the worktree that owns it (K and D10 from A1, D1/D12 A2, D2/D4 A3, D3 A4, D5 A5, D6/D7 A6, D8/D13 A7, D9/D11 A8) — 475 rows, 453 distinct ids (22 shared `CQ-*` ids appear in two packets and keep one row per packet). `_notes/answer_kind_table.py` applies the method in `answer-kind-table.md` (R1 published · R2 assessment · R3 materialized · R4 retrieved, first match wins; the declared kind stands unless a rule clearly applies), the explicit `RULINGS` dict (each with its reason), and derives trace and freshness from the ruled kind plus four explicit sets (criterion-computed, lineage, fetched-at-query-time, GDS-streamed). It warns when a ruling or set names a row that no longer exists or whose declared kind changed, so a re-run after any owner edit shows which rulings to revisit. No packet's `02-questions.md` was edited: rulings are proposals to the owners and the synthesizer.

**One principle sharpened in this pass.** The kind names the answer's *payload* — the record a user cites back — not every record the query touches. So a question returning the content or verdict of one published Report is published (Q-K-08, Q-K-17, Q-D2-28), while a question about the live status of many records is retrieved (stale-report queue Q-D10-13, reverse citations CQ-AX-11, integrity audits CQ-AX-08); a list that mixes assertions, assessments and associations is retrieved, each element keeping its own kind (Q-D2-14).
