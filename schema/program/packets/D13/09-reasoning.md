## Decisions (alternatives considered, what was cut and why)

### Node types

**Event — kept (D13 owns it; coordinator default and D7, D3, D8 research notes agree).**
- *Alternative A: no Event node; events as Assertions only* (predicate READOUT_OCCURRED with subject = study or compound). Rejected: Q-D13-05/06/14 traverse event-to-event links, and an Assertion cannot be the endpoint of a typed domain relationship without becoming a hub; several artifacts about one occurrence (FC3: 8-K, EX-99.1, openFDA record, FDA BT list row) need one identity to attach to.
- *Alternative B: one node type per family* (RegulatoryEvent, FinancingEvent, ClinicalEvent …). Rejected: every timeline question spans families; the pinned split into 26 categories + free eventType was already redundant. One `eventKind` enum with typed qualifiers (`readoutStage`, `primaryEndpointStatement`, `approvalPathway`, `designationType`, `discontinuationScope`) covers every artifact interviewed in the research stage.
- *Alternative C: separate Event and EventVersion (state attachment) to hold clock history.* Rejected: the kernel already holds history in Assertions (recorded time), and the clocks are materialized from named assertions (pinned rule kept: `timeAssertionUid` etc.). A state node would duplicate the Assertion.
- *Clocks:* five are kept apart (CQ-TM-03): event date (`startedAt` ← EVENT_OCCURRED), document/filing time (SourceSnapshot.publishedAt of the 8-K — not an Event clock), announcement (`announcedAt` ← EVENT_ANNOUNCED), legal effect (`effectiveFrom` ← EVENT_EFFECTIVE, INSTANT with `localTimeZone`, FC7 "5:00 p.m. Eastern Time"), and recorded time (Assertion.recordedAt). Registry start date vs sponsor "first participant dosed" (FC9) = two EVENT_OCCURRED assertions by two asserters; `clockRule` names which one the node displays.
- *Guided dates:* stay as EVENT_SCHEDULED assertions on a PLANNED Event (directive and research: slips must be findable, Q-D13-11). The node materializes only the latest window (`scheduledFrom`, `scheduledTo`, precisions, `scheduleAssertionUid`). Alternative considered: a `guidedDate` property overwritten on each restatement — rejected, it destroys exactly the history Q-D13-11 needs.
- *HALF_YEAR:* not needed. "In the first half of 2023" (FC1) is the half-open window [2023-01-01, 2023-07-01) with MONTH precision on both bounds; "by the end of 2025" (FC10) is [unknown, 2026-01-01) with the start basis UNKNOWN. A kernel enum value would only be needed for a single-bound statement with half-year granularity, which no captured artifact uses. Recorded as resolved in 11-open-questions.md.
- *Harm events with no filing:* nothing in the model requires an 8-K or regulator record; one EVENT_OCCURRED assertion with a locator suffices (BioAge, FC6). Corroboration is a computed answer (Q-D13-22), not a gate.
- *Not on Event:* impact level, breakthrough flag, sentiment, hype, amounts (D7 money assertions), share-price change (D7 / predicate-only REPORTED_MARKET_MOVE), any good/bad value. `primaryEndpointStatement` was examined against directive 3.2: it captures what the source *states* about a trial endpoint (FC1 "Were Met", FC7 "no statistically significant difference"), is materialized from a FIELD assertion with a locator, and is named "Statement" so it cannot be read as a BellLabs verdict; the judgment of the result is a D3 StudyResult or an Assessment.

**Frontier — kept (directive 3.7; vocabulary node).**
- *Alternative A: tags (`frontierKeys` list on Event and Study).* Rejected in the vocabulary: loses asserter, vocab version and supersession; a classification is a curator's claim and must be adjudicable.
- *Alternative B: frontier as an enum value.* Rejected: Frontier is the subject of assessments, reports and claims (Q-D13-29/30, claims about a field), which need a Subjectable node, and its definition/synonyms/targetKeys are needed for linking.
- *Hierarchy and target relevance as properties* (`parentKey`, `targetKeys`): two levels, ~25 nodes; an `IN` filter is enough; no relationship type spent (same choice as D5 targets).
- `label` is stored in the Entity field `name` (one fewer property; vocabulary 0.2.0 says so).

**Considered and not admitted as nodes:** NarrativeArc (→ kernel Report), EventImpactAssessment (→ kernel Assessment), Conference (→ D9), Community (cut), Milestone (a lens over eventKind + qualifiers + computed firstness), Breakthrough (computed criteria or an Assessment), Forecast (snapshot + FORECASTS assertion), FinancingRound (a FINANCING Event; D7 agreed), Guidance (EVENT_SCHEDULED assertions). See `06-node-register.yaml` `deferred` and `mergedInto`.

### Relationship types

**ON_FRONTIER (asserted; Event→Frontier, Study→Frontier).** Every frontier question traverses it (rule 6 satisfied: Q-D13-01 et al.; pattern 03#Q-D13-01; populated by `agent:d13-frontier-curator`; fixture `madrigal-maestro-nash-topline-8k`). Declared as `Event.frontiers` (OUT) and `Frontier.studies` (IN) so D3 Study spends no field and ON_FRONTIER stays one D13-owned type. *Alternatives:* D3 declares `Study.frontiers` (rejected: splits ownership of one relationship type across modules); a `Frontier.events` inverse field (rejected: `events(where: { frontiers: … })` and the connection filter answer the same GraphQL need; would add a pair and ~5 KB). Vocab version: the 0.1.0 vocabulary put `vocabVersion` on the edge; the kernel edge-property type (AssertedEdgeProperties then, AssertedRecordedProperties since the check stage) is not extended for one display field (a superset type is for filtered qualifiers, M11), so the version is the classification Assertion's qualifier `frontierVocabVersion=<semver>` (Q-D13-28 reads it there).

**LEADS_TO (asserted; Event→Event).** Replaces pinned CAUSED_BY with the forward direction. Projection gate (the hard part the research found): the Assertion must have speechAct STATES, a locator that states the basis, and a SUPPORT Adjudication DIRECTLY_SUPPORTED / SUPPORTED_WITH_QUALIFICATION; temporal wording ("following", "after") is adjudicated CONTEXT_ONLY and stays a computed FOLLOWS. FC2 is the test: "as a result of the Company’s announcement of Phase 3 MAESTRO-NASH clinical trial topline results" projects; "The financings secured following the positive topline readout" does not. The 0.1.0 vocabulary's basisKind requirement (CITED_FROM_PRIOR_WORK / DIRECT_MEASUREMENT) was dropped: a sponsor's statement about its own contract or decision fits neither value (11-open-questions.md, first-party BasisKind).

**RESPONDS_TO (asserted; responding Event→stimulus Event).** Agency, kept separate from LEADS_TO. *Alternative:* one EVENT_LINK type with a `linkKind` property — rejected: every chain query would have to filter the property, the kernel edge-property type has no such field (it would need a custom type), and the two are asked separately (Q-D13-05 chain vs Q-D13-14 responses). Cost of keeping two: one relationship type, one pair.

**DOCUMENTED_BY_RECORD (asserted; Event→D8 RegulatoryRecord) — promoted in the adversarial-review pass.** The review showed the APPROVAL / REGULATORY_DESIGNATION / RECALL / ENFORCEMENT_ACTION Event repeated what D8's RegulatoryRecord already holds (issuer, addressee, date, jurisdiction): INVOLVES REGULATOR and APPLICANT were second copies of ISSUED_BY and ADDRESSED_TO. Now the Event points at the record and Q-D13-12 / Q-D13-14 read the regulator and holder through it in two hops; REGULATOR and APPLICANT stay only for events no D8 record documents (a clinical hold or a designation known only from the sponsor, a submission). *Alternatives:* keep the predicate-only link (three hops through an Assertion node per regulatory question, and the duplicate role edges stay); drop REGULATOR / APPLICANT entirely (loses holds and submissions that have no public record). Cost: one relationship type and one pair (+5.1 KB printed, +4 inputs), within budget (5/14, 7/35). Jurisdiction and designationType stay on the Event (Q-D13-04 filters them, and many events have no record), but their FIELD assertions cite the record's locator when one exists, so there is one span, not two sources.

**INVOLVES (asserted; Event→Organization, Event→Person, role on the edge).** Q-D13-03 (value 1) and Q-D13-06 traverse Frontier ← Event → Organization with a role filter; D7 asked D13 to own the event-role edge and declares no inverse. *Alternatives:* (a) role as a qualifier on the authorizing Assertion with the plain kernel AssertedEdgeProperties — rejected because the role filter then needs a join on `assertionUid` in every investor query and is invisible to GraphQL filters; (b) one relationship type per role (SPONSORED_BY, FINANCED_BY, REGULATED_BY …) — rejected, multiplies types for one fact shape; (c) a 2-member union target `EventParticipant` — rejected for two typed fields (same pairs, no union input family). Chosen: `EventRoleEdgeProperties` = the kernel base fields verbatim + `role: EventRole!`, the construction the kernel itself uses for IdentifierLinkProperties and the pinned W18 profile of the same name. Model stage: base AssertedEdgeProperties, measured 8.9 KB, contested in 11-open-questions.md. Check stage: the kernel accepted domain-local superset types (M11) and published AssertedRecordedProperties (M10); the base is now AssertedRecordedProperties, measured 6.1 KB with the EventRole enum. Adversarial-review pass: `roleTitleVerbatim` removed — kernel M11(3) admits only qualifiers a question filters on, and the printed title is display text, so it is the authorizing Assertion's qualifier `roleText=<label>` (D3 does the same for HAS_STUDY_ROLE); −768 bytes. EventRole gained BORROWER (the financed party of a loan issues no securities, fixture a04) and lost AWARDING_BODY / AWARDEE (an award's funder and recipients are D7 Award AWARDED_BY / AWARDED_TO; an AWARD Event points at the Award through EVENT_ABOUT).

**Predicate-only (kernel Assertion.predicate, no typed edge):** EVENT_ABOUT (what an event is about: the most-used one; 2-hop through the Assertion; one per Event carries `primary=true` for the identity rule; promote with ≤ 6 members if Q-D13-05/16 latency is measured too high), EVENT_OCCURRED / SCHEDULED / ANNOUNCED / EFFECTIVE / CANCELLED (time literals), CONTINGENT_ON (→ confirmatory Study), PRESENTED_AT_CONFERENCE (→ D9 Channel EVENT_SERIES; edition as qualifier), REPORTED_MARKET_MOVE (subject Event, object Organization; owned here), FORECASTS, FINANCING_AMOUNT (owned here; `iso4217:` unit, amountKind / amountBasis qualifiers), and the qualifier FIELD predicates. Each has its promotion question in `05-relationship-register.yaml`. DOCUMENTED_BY_RECORD left this list in the adversarial-review pass (typed, above).

**Event identity (rewritten in the adversarial-review pass).** The review found the model-stage rule unsound: a key that includes the time "at its stated precision" changes when a window is re-guided, when PLANNED becomes OCCURRED, or when a later source gives a more precise date, and every change would mint a second Event — defeating Q-D13-11. The fixtures had also bent it (the planned NDA submission keyed on the later actual date; financing keys used an INVOLVES participant as "primary subject" and an undeclared suffix). Now: `identityKey` is minted once and frozen (kind | primary subject | jurisdiction | first-stated time at its precision | discriminator); the primary subject is marked on its Assertion (`primary=true` on one EVENT_ABOUT, or on the ISSUER / BORROWER / ACQUIREE INVOLVES for deals); a FINANCING discriminator (instrument) separates two financings of one issuer on one day (fixture: the loan tranche and the ATM sales, both 2022-12-19); and matching compares kind, primary subject, jurisdiction and overlapping windows, never key strings, with merges only through an accepted EQUIVALENCE Assessment. Every fixture Event records `mintedFrom`.

**Computed, not stored:** FOLLOWS (method valid-time-order-v1), ACTIVE_ON_FRONTIER (who is active on F), REPORTED_IN (corroboration), "furthest milestone" and firstness (frontier-ladder), breakthrough by criterion.

**Cut from pinned W18 (22 relationship types → 5):** CAUSED_BY and FOLLOWED_BY (merged/computed), EVENT_ABOUT (kernel pattern), DOCUMENTED_BY_RECORD (kept, typed, one member: D8 RegulatoryRecord instead of the 5-member EventRecordTarget), HAS_EVENT, HOSTS_EVENT, SPEAKS_AT, ATTENDS, EXHIBITS_AT (folded into INVOLVES roles or cut), SPONSORS_CONTENT, RECORDING_OF, PRESENTED_AT (D9/D7), ARC_ABOUT, ARC_INCLUDES_EVENT, ASSESSES_EVENT, IMPACT_ON (kernel Report/Assessment), REPORTED_IN, SUPPORTED_BY, SUPPORTED_BY_CHUNK, SUPERSEDES, WAS_GENERATED_BY (computed or kernel). Unions EventParticipantTarget (3), EventSubjectTarget (15), SponsorableTarget, EventRecordTarget (5) are gone.

## Bitemporal decision per edge

| edge | edge-property type | valid time on the edge | recorded-time episode | why |
| --- | --- | --- | --- | --- |
| ON_FRONTIER | kernel AssertedRecordedProperties | **none** (no valid-time fields) | **yes** | a classification has no validity of its own; "what did the frontier timeline look like as recorded on R" (CQ-TM-01) and reclassification after a vocab bump (Q-D13-28) need recordedFrom/recordedTo |
| LEADS_TO | kernel AssertedRecordedProperties | none | yes | the link's time is the two events' clocks; what changes is BellLabs' belief (a retracted statement, a failed adjudication) |
| RESPONDS_TO | kernel AssertedRecordedProperties | none | yes | same as LEADS_TO |
| INVOLVES | EventRoleEdgeProperties (AssertedRecordedProperties fields + role) | none | yes | an involvement has no validity beyond the event; a corrected role is a superseding assertion |

So **no D13 edge needs a valid-time episode**. ## Risks

- **Materialization drift.** Event properties are copies of Assertions; if the executor does not re-materialize on every superseding assertion, the node shows stale clocks or status. Mitigation: `timeAssertionUid` / `scheduleAssertionUid` pointers make drift detectable (pointer to a closed assertion); the CQ-TM-01 pattern re-derives from assertions instead of reading properties. Executor work is required (11-open-questions.md, owner).
- **Custom edge-property type.** `EventRoleEdgeProperties` is sanctioned by the kernel's superset rule (M11) and, since the adversarial-review pass, follows all of it: base fields verbatim and in order, then only `role`, the one qualifier questions filter on (M11(3)); the printed title is the Assertion qualifier `roleText`. Residual risk: when `AssertedRecordedProperties` gains a field, D13 must add it in the same synthesis pass (M11 rule 5).
- **Event identity / dedup.** Without a shared external id, two runs can mint two Events for one occurrence (8-K vs press release vs registry). Guard: a frozen mint-time `identityKey`, candidate matching on kind + primary subject + jurisdiction + overlapping window, and merges only through an accepted EQUIVALENCE Assessment (adversarial-review pass). Fixtures exercise two artifacts → one Event (FC3 openFDA + 8-K) and a PLANNED Event that later occurs without re-keying (the NDA submission and the approval). Residual risk: a doubtful match the executor resolves wrongly; the EQUIVALENCE Assessment makes it reviewable, not impossible.
- **Ambiguous causal language.** LEADS_TO/RESPONDS_TO depend on SUPPORT adjudications of "following"-type spans; if the verifier's rubric does not distinguish stated basis from temporal order, investor chains will contain false causation. FC2 is the regression case.
- **Frontier classification is a judgment.** ON_FRONTIER is a curator's claim; over- or under-attachment skews "first on F" answers. The vocab's admission and 1–2 frontier rule, the `frontierVocabVersion` qualifier and supersession make it auditable, not correct.
- **2-hop EVENT_ABOUT.** The most common join (event ↔ compound/study) goes through Assertion nodes; with millions of assertions this needs an `Assertion(predicate)` index and may need promotion to a typed edge.
- **Executable weight of Event.** 38 scalar properties make Event the heaviest D13 type (about 36 KB printed). If the synthesizer needs more savings, the next cut is moving `endedAt` and the scheduled precisions to Assertion-only reads.
