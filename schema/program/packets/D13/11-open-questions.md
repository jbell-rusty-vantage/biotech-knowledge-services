## Conflicts between the contract, the directive, the kernel pattern and D13's findings

1. **Domain edge-property type for INVOLVES.** The kernel pattern says domain modules use only the four kernel edge-property types (`packets/K/04-schema-proposal.graphql` section header "the only ones a domain module uses"). D13 declares `EventRoleEdgeProperties` = the AssertedEdgeProperties fields verbatim + `role: EventRole!` + `roleTitleVerbatim`, built the way the kernel builds IdentifierLinkProperties, because the investor questions filter participants by role (Q-D13-03, Q-D13-06, Q-D13-14). Fallback if refused: plain AssertedEdgeProperties, role in the authorizing Assertion's qualifiers, role filters as Cypher joins on `assertionUid` (GraphQL loses the filter). · Evidence: measured cost 8.9 KB printed for the type + enum (09-reasoning.md); whether D7 (HOLDS_STAKE/HOLDS_ROLE with stake properties) needs the same extension — if two or more domains do, the kernel should publish the rule "AssertedEdgeProperties + typed qualifiers" instead of each domain improvising. · Owner: **kernel** (A1), with D7. **Resolved by the kernel (check stage, 2026-10-08):** domain-local edge-property types are allowed as supersets of a kernel base type (K 09-reasoning.md M11, change 2); `EventRoleEdgeProperties` now lists the `AssertedRecordedProperties` fields verbatim and in order, then `role` and `roleTitleVerbatim`. **Adversarial-review pass:** `roleTitleVerbatim` removed (M11(3): a field that only reproduces the source's wording stays in Assertion.qualifiers, here `roleText=<label>`); `role` is the only qualifier.
2. **Valid time on D13 edges.** The kernel mandates AssertedEdgeProperties (bitemporal episode) on every asserted edge; D13's four edges use only the recorded-time half (valid bounds null, basis UNKNOWN). Directive rule 9 asks for episodes "on the smallest number of edges that need" them. · Evidence: the D13 questions (03-retrieval-patterns.md) never read edge valid time; the printed saving of a recorded-only asserted edge-property type would be a few filter fields per relationship. · Owner: **kernel** (low priority; D13 is fine either way). **Resolved by the kernel (check stage):** `AssertedRecordedProperties` published (M10, change 1); all four D13 relationship types use it (directly or as the INVOLVES base); measured −5.7 KB printed (09-reasoning.md, compile check).
3. **Vocabulary version on the ON_FRONTIER edge.** `vocab-frontiers.yaml@0.1.0` put `vocabVersion` on the edge; the kernel edge-property type has no such field and must not be extended for one field. **Resolved here:** the classification Assertion carries the qualifier `frontierVocabVersion=<semver>` (vocab 0.2.0 updated). · Evidence that would reopen it: Q-D13-28 needing a GraphQL filter on the version (it is value 3, agent-only). · Owner: **D13**.
4. **L3 size lever (program-wide?).** `@filterable(byValue: false, byAggregate: false) @sortable(byValue: false)` on scalar bookkeeping fields no question filters (assertion-uid pointers, precisions, bases, notes) saved 11.6 KB (−14 %) of D13's printed cost with no loss of readability.
