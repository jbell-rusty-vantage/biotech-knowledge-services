## 3. Activity ↔ Mission Control (ADR 0004, directive §4)

- **Identity granularity — needs a decision.** The kernel says one Activity per run, identity `(externalRunSystem, runId)`, with single-valued `operationId`, `operationKind`, `intentDigest`, `planDigest`, `receiptId`. Mission Control's annex identity is "mission/run/activation/attempt, generation and stable semantic effect key", and one run can plan/apply several intents (each with its own receipt). Options: (a) one Activity per run; intents/receipts that run applied are listed as `receiptIds: [String]` / `intentDigests: [String]` (additive, list-valued); (b) one Activity per applied intent (identity `(externalRunSystem, runId, operationId)`) with `WAS_INFORMED_BY` to a run-level Activity. (a) is slimmer and keeps "what did run R write" a single hop; (b) answers "which intent wrote X". Recommendation: **(a)** — the intent marker (`KsIntentMarker`, ADR 0004) already ties each receipt to its graph effects, and Q-K-04 / Q-K-07 need the run, not the intent. Do not add `attemptId`: retries keep the semantic effect identity and the executor's marker dedupes them, so an attempt never writes distinct graph content. Record as an open question so the owner sees it.
- **activityKind vocabulary**: intents today send `EXTRACTION` (example intent); the kernel enum is RESEARCH, INGESTION, VETTING, EVIDENCE_MISSION, VERIFICATION, PROJECTION, ANSWER. Executor change P3 (already listed) maps the old fine-grained values to `operationKind`.
- **"What changed between two runs" (Q-K-07)** has no database support: the annex states "A schema/SDL digest is not a graph data revision; do not invent a knowledge-sequence equivalence", and Neo4j has no `as-of`/`since` (contrast Datomic `as-of`, `since`, `history`; XTDB system time). The pattern must therefore be built from `lastWriterRunId` (nodes and edges), `recordedAt` / `recordedTo`, `supersedesUid`. This makes the relationship-property indexes in P13 (`lastWriterRunId`, `assertionUid`, `relationshipUid`) **required**, not optional, and makes executor change P9 (WAS_GENERATED_BY on update) the cheapest way to answer Q-K-05. One subtlety for the fixtures stage: `lastWriterRunId` is overwritten by a later run, so "what did R1 write" for a node later touched by R2 must come from `WAS_GENERATED_BY` (multi-valued), not from the property.
- **Receipt reconciliation**: the KS receipt lists `created.nodes / relationships` per proposal and `affected[]`; a check-stage query can compare that list with the graph's `WAS_GENERATED_BY` set for the run (Q-K-04 fixture expectation).
- **Evidence mission**: a Mission Control mission whose output contract is an evidence report; MC states "A goal completes when the verification policy accepts the output contracts, not when an agent says so" (`mission-control-general/MISSION_CONTROL_SPEC.md`, the paragraph before §4.4). Mission `superseded` and Attempt `rejected` are MC states; the graph only needs the Activity and the Report.

## 4. Claim lifecycle (directive 3.4) — observations from FC-2 / FC-4 / FC-5

- **Refined propositions.** The resveratrol–SIRT1 record shows the judged proposition drifts: "directly activates SIRT1" (2003) → "substrate-specific" (2005) → "not direct" (2010) → "directly activated through an allosteric mechanism … substrates such as PGC-1α and FOXO3a" (2013). An evidence report must say which proposition it judged. Cheapest model: each variant is its own `Claim` (propositionHash differs); the link between a general claim and its qualified variant is an `Assessment` of kind EQUIVALENCE with `assessmentSubkind: REFINES` (no new relationship type), or an additive `Claim.refinesClaimUid` property. Recommend the assessment (it carries who decided and why); flag in open questions.
- **Third-party verdicts are Assertions, never our Assessments.** A ClaimReview, a regulator finding or a journal's expression of concern is a statement by another asserter. Model: Source (the review page) → snapshot → locator on the rating → `Assertion {assertionKind: FIELD, predicate: RATES_CLAIM, value: "Unsupported", qualifier: the reviewer's scale, subject: the Claim}` (not `assertionKind: CLAIM` — the review is not an occurrence of the claim itself) with `ASSERTED_BY` the reviewing organization (D7). The mapping from their scale to the lattice is a D10 method (versioned) feeding Q-K-27; our verdict lives only on our Adjudications / Reports. This also keeps CQ-EV-02 ("a source assertion, a BellLabs adjudication, or a derived retrieval shortcut?") answerable by label alone.
- **Retellings and cited support.** Active Motif's "Activates SIRT1 … (ref 2)" cites Howitz 2003; MegaResveratrol retells Pacholec 2010. Represent a retelling occurrence as an Assertion with `basisKind: CITED_FROM_PRIOR_WORK` and `DERIVED_FROM` → the primary occurrence Assertion (kernel relationship already exists on Assertion; PROV-consistent). Independence counting (Q-K-21) then = count of distinct roots under DERIVED_FROM among supporting occurrences, plus `independence` on evidence edges (§2). Retelling *fidelity* (did it change scope/qualifier) is a D9 RETELLING_FIDELITY assessment.
- **Disposition semantics.** IGNORE / MONITOR / RESEARCH confirmed. MONITOR needs a trigger: new occurrences or new evidence after the vetting date (Q-K-26 uses the same pattern for stale reports). No new type.
- **Verdict of an evidence report.** Use the 15-value lattice as Wave 0 says; FC-2 is likely MIXED_OR_CONFLICTING for the general claim and SUPPORTED_WITH_QUALIFICATION for the refined one — the fixtures stage should test both, which exercises the refinement link.
- **Claim occurrence dates.** Interested-party pages often have no machine-readable date (FC-4); Science Feedback's JSON-LD has three different dates for one review (FC-5). The kernel's `ValidTimeBasis` (STATED_BY_SOURCE, PUBLICATION_PROXY, OBSERVATION_ONLY, INFERRED, UNKNOWN) is sufficient; fixtures must use OBSERVATION_ONLY when the page states no date.

## 5. Time and revision

- PubMed exposes five clocks on one record (received, accepted, entrez/pubmed, medline, pmc-release) plus `DateRevised`; Crossref adds `created`, `deposited`, `indexed`, `published-print`, `published-online`, and per-update `updated`. The kernel needs only: `SourceSnapshot.publishedAt` (+ precision), `retrievedAt`, `Assertion.validFrom/To` (+ basis), service `recordedAt/recordedTo`. Everything else is a qualifier in `selectorJson`/payload. CQ-TM-03 is answered by these four.
- **Retraction status asserted by two authorities** (Crossref `source: publisher` vs `retraction-watch`, PubMed `RetractionIn`). Recommendation: the status is an Assertion (predicate `HAS_REVISION_STATUS`, value RETRACTION / EXPRESSION_OF_CONCERN / ERRATUM …, subject the Source, asserter Retraction Watch or the publisher, validFrom = the authority's date) **and** the cache `SourceSnapshot.revisionKind` on the new capture. That answers Q-K-22's "asserted by whom" without a new type.
- **Late arrival (CQ-TM-02)**: FC-3's retraction validFrom 2025-06-30, recordedAt 2026-10-08 is the canonical test: an as-of query for recorded date 2026-01-01 must return the paper as unretracted.
- **Registry history is unreachable** (ClinicalTrials.gov 403). Bitemporal claims about registry content can only be made from BellLabs snapshots; never set validFrom of a registry fact earlier than the first snapshot unless the registry states it (basis STATED_BY_SOURCE).
- Edges that need episodes: unchanged from Wave 0 (HAS_IDENTIFIER, domain asserted edges, state attachments). Research found no K question that needs an episode on a kernel structural edge.

## 6. MENTIONS / SUPPORTS / CONTRADICTS in practice (directive 3.8)

- The effectiveness path is demonstrated on FC-1 (PMC JATS): question → D9 chunk (paragraph) → MENTIONS(resveratrol, SIRT1) → locator → assertion → snapshot digest; re-selection compares `selectedContentDigest`. Paragraph boundaries in JATS are a natural chunking, but the **chunk is not the locator**: the locator is the sentence span with its own selector.
- Two observed traps for the fixtures: (1) the same sentence appears in two renditions (PubMed abstract XML and PMC JATS abstract) — two Sources, two locators, one proposition; independence counting must not count them twice (same `DERIVED_FROM` root or an EQUIVALENCE assessment between the Sources); (2) MegaResveratrol's key sentence occurs twice in the HTML — a TEXT_QUOTE selector needs prefix/suffix or a position to be unique.
- scite-style "mentions" (citing sentence names the work without support/contrast) are not evidence; if ever ingested they are MENTIONS-class derived edges with a method version.

## 7. Identifier scheme register (seed) — additions and a column

- Add schemes needed by K fixtures and surveyed sources: `RW_RECORD` (Retraction Watch record id, issuer Crossref/Retraction Watch, pattern `^[0-9]+$`), `CHEMBL` (`^CHEMBL[0-9]+$`), `UMLS_CUI` (`^C[0-9]{7}$`), `CHEMSPIDER` (`^[0-9]+$`), `NANOPUB` (trusty URI artifact code `^RA[A-Za-z0-9_-]{43}$`, issuer: the signing agent; low priority), `NIHMS` (author-manuscript id, `^NIHMS[0-9]+$`, issuer NIH) for rendition identity. Patterns to be checked against Bioregistry before the register is final (I verified only `unii`, `pubchem.compound`, `clinicaltrials`).
- Add two columns: `bioregistryPrefix` and `wikidataProperty` (e.g. UNII → `unii`, `P652`; PUBCHEM_CID → `pubchem.compound`, `P662`; NCT → `clinicaltrials`, `P3098`). Benefit: the register becomes checkable against Bioregistry's `pattern` / `uri_format`, and Wikidata crosswalks map mechanically. D11 (A8) owns the bridge table; K owns the register.
- Rule confirmed: a crosswalk value read from Wikidata is an Assertion by the Wikidata community with `authority: AUTHORITATIVE_AGGREGATOR` or `SECONDARY` and its own reference — it can propose identity (RESOLUTION assessment) but never establish it alone (Q-K-29 detects conflicts).
