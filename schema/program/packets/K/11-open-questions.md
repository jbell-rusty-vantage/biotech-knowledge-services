## Questions

1. **Adopt L1 (`@filterable(byAggregate: false)` on every relationship) and L2 (`@mutation(operations: [])` on every type) program-wide?** They are part of the published kernel pattern because the numbers are decisive (−74% bytes and −38% inputs per type respectively), but 00-DIRECTIVE section 2 names only `aggregate: false` and `nestedOperations`. Evidence: `lever-experiments.md`. Owner: **owner** (decision 0001).
2. **Enable `excludeDeprecatedFields` (all five flags) in `apps/graphql-api`?** −66 to −85% printed bytes with no SDL change, but deprecated filter spellings disappear for clients. Evidence: a grep of client queries (Python client, evals, agent skills) for deprecated `_EQ`/`_IN`-style filters and aggregate filters outside connections. Owner: **owner**.
3. **The pairs metric of `schema-workspace map` expands interface targets per implementer** ("the executable schema expands every union or interface target into one input/filter family per concrete member"). Measured: true for unions, false for interfaces under the kernel pattern (≈ 0 per implementer). For kernel + template the map reports 62 pairs where `packet-check` reports 34. The synthesizer should report both, and budgets should use the union-expanded / interface-collapsed count. Owner: **owner** (S, tooling).
4. **Generic `Assessment` vs domain assessment types.** The kernel offers one `Assessment` with `assessmentKind` / `assessmentSubkind`; a domain that needs typed, filterable assessment properties (e.g. D3 evidence grade components, D5 interaction severity) must request kernel fields. Evidence that would decide splitting: more than ~25 requested properties or more than 12 relationship fields on Assessment. Owner: **kernel**, with D3, D5, D8, D9.
5. **`ASSESSES` from a domain node into an Assessment / Report.** Domains do not get an inverse field on their own types (it would be a per-type cost); they read assessments from the Assessment side. If a domain question needs a forward field (e.g. `Target.assessments`), it declares it on its own type with `direction: IN` and lists `K.Assessment` in its seams. Evidence: domain questions in 02 that traverse it. Owner: each domain.
6. **PolicyVersion as a node.** Kept as an id string on Report and Activity. D10 decides whether a question traverses policies ("which answers were published under policy P and are now outside it") strongly enough to promote it. Owner: **D10** (A1).
7. **WAS_GENERATED_BY on update.** P9 makes WAS_GENERATED_BY mean "this run wrote (created or updated) this node", the cheapest way to answer "which missions touched X". Alternative: a property list of run ids on the node. Evidence: fixture with two runs over one entity (planned K fixture 3). Owner: **kernel**.
8. **Coordinator premise.** The computed task said an earlier A1 agent had already published Wave 0 (`09-reasoning.md`, `04-schema-proposal.graphql`, `lever-experiments.md`, a domain template) and that domain agents were compiling against it. On disk (2026-10-08, this worktree and siblings A2–A8, S) there was no `packets/K/` at all; this stage produced Wave 0 from scratch. Domain agents that drafted against the placeholder `Subjectable` interface are compatible: `Subjectable` is the published interface name. Owner: **owner** (coordinator).
9. **Agent acting on behalf of an Organization** (pinned ACTED_ON_BEHALF_OF) is deferred; if D7 needs "which organization's agent asserted this", D7 declares it with a seam. Owner: **D7**.
10. **Directive rule 3 says structural edges use `[CREATE, CONNECT]`.** Kernel structural edges that link a record to existing nodes (HAS_SUBJECT, HAS_EVIDENCE, ASSESSES, DERIVED_FROM, …) use `[CONNECT]`, a tightening; with `@mutation(operations: [])` neither generates inputs. Owner: **owner** (confirm).
