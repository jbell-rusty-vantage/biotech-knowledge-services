## What was exercised in the fixtures stage, and what broke

- **Fresh re-fetch of every fixture source** (rows 21–24 of the tool log): 12 API/raw captures came back byte-identical (DSLD ×5, Shopify live + Wayback, Economist CSV + README, openFDA, eCFR, SEC 10-K HTML), and 3 of 8 Firecrawl renditions too (McDonald's, FDA ×2); 5 Firecrawl renditions changed bytes on the same day (iHerb ×2, Amazon, camelcamelcamel, NSF), every quote was still found, offsets moved. Consequence: locators on scraped pages must carry quote + prefix/suffix and re-anchor; digests alone do not survive a re-fetch.
- **SEC 10-K text projection**: the research-stage normalization was not written down; this stage recovered it by testing candidate rules until the digest matched (`edgar-text/v5`). A text projection must be registered with its rule at capture time (verification.v1 canonicalProjectionArtifact).
- **New commerce captures for the harm fixture**: `firecrawl search` found the MOGO Amazon store and ASIN B084FRXSTX; Firecrawl scraped it ("Currently unavailable.", no seller); the brand's Shopify `products.json` returned an empty catalog.
- **Identifier validation**: GS1 check digits computed for every GTIN in the fixtures (all valid) and for the tracker's EAN `085001531185` (invalid → staged as a mention, not attached).
- **Intent contract**: all seven `intent.json` files validate against `@bks/contracts` `IngestionIntent` (zod, `packages/contracts/dist`), with every proposal ref and evidence ref resolving. Not expressible in intent v1 (kept in `assertions.yaml`): Assessments, Adjudications, claim occurrences (CLAIM + OCCURRENCE_OF), DERIVED_FROM inputs, Assertion qualifiers, asserters on `state.attach`/`identifier.attach`, predicate-only object assertions (11-open-questions OQ-D6-18). The intent's `statedAsOf` maps to the kernel's `Assertion.validObservedAt` (check stage; OQ-D6-19 mostly resolved).
- **Shell findings**: Windows Python needs Windows paths (`cygpath -w`); mingw curl reported HTTP 200 but wrote no file when given an absolute `/c/...` output path from another working directory (relative path worked).

## What needs custom tooling

1. A **listing resolver** (ASIN/retailer id ↔ GTIN ↔ Package) with GS1 check-digit validation and an EQUIVALENCE assessment output; Amazon search does not resolve UPCs, so discovery runs through web search (Firecrawl/Tavily) today.
2. A **re-anchoring locator store** for scraped commerce pages (quote + prefix/suffix + rendition digest), because Firecrawl renditions of the same page change within hours.
3. A **text-projection registry** (rule name + version + digest) for HTML filings and pages, so that TEXT_QUOTE offsets are reproducible (edgar-text/v5 is the first entry).
4. **Recall-to-listing matching** from free-text lot codes and channel lists (openFDA) to listings and lots, with typo-tolerant firm and domain resolution.
5. **OCR for label images** (Nutrition Facts panels as images; DSLD label PDFs not fetched yet) and a data.gov key for FDC.
