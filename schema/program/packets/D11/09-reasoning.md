## Decisions (alternatives considered, what was cut and why)

### 1. The action-space registry stays config: no `ToolCapability` node

- Chosen: `tooling/action-space.yaml` (PLAN 6.3 fields, versioned in the repo; 59 D11-local entries until the cross-packet pass, now 167 merged entries from all fourteen packets with an alias map, generated by `_notes/action-space/build-action-space.mjs`). The graph refers to a tool only by its entry id, as the prefix of the kernel `SourceSnapshot.captureMethod` (`<id>/<version>`) and as `CaptureAttempt.toolId`.
- Alternatives:
  - (a) A `ToolCapability` / `SourceAccessProfile` node with `CAPTURED_WITH` edges from snapshots and attempts. Cut. No question traverses past the tool: Q-D11-01 and Q-D11-20 read the registry and join counts by id. The node would also be a ~60-member, low-cardinality vocabulary that every capture points at, which is the modeling skill's "low-cardinality value as node" supernode anti-pattern.
  - (b) Making the tool a kernel `Agent`. The kernel already lets a capture Activity name its Agent (`toolVersion`), and CQ-PV-03 uses that. But readiness, auth and limits are properties of a route at a date, not of an actor, so they stay in config.
- Consequence: readiness never becomes a property of a Source or an entity, which keeps 00-DIRECTIVE 3.2 (no good/bad on entities).

### 2. Failed, empty and partial captures are a node: `CaptureAttempt` (absorbs pinned SourceDiscoveryRecord)

- The research stage recommended 0 node types. The model stage overturned that for one record, because two questions cannot be answered from the kernel alone:
  - Q-D11-17 (D11, value 1, harm) asks what failed in mission M.
  - K:CQ-AX-04 (owner K: value 2, neutral; D11 had mis-copied it as value 1, harm, corrected in the adversarial review) asks why an answer is empty. Most of its states are kernel records (measured absent = POSITIVE NO_* assertion; not reported = FIELD_NOT_REPORTED on a COMPLETE snapshot). The one thing the kernel cannot hold is "unknown: blocked" versus "unknown: never queried" for a subject and tool, because a failed request leaves no record.
- A failed request leaves no SourceSnapshot (the ICTRP timeout left no bytes at all), so the kernel has nothing to hang the fact on. A1 deferred SourceCoverageRequirement and SourceDiscoveryRecord to D11's registry on the ground that "no user question traverses them". D11's evidence contradicts this for the discovery record, and the contest is in `11-open-questions.md`.
- Alternatives:

| option | answers CQ-AX-04 / Q-D11-17? | cost | verdict |
| --- | --- | --- | --- |
| (a) kernel `SourceSnapshot` gains `captureOutcome`, `failureKind`, `httpStatus` | Q-D11-17 yes. CQ-AX-04 only partly: there is no subject link and no record when no bytes arrived. Every search URL and error page would become a `Source` (identity = canonicalUri), polluting the evidence layer. | +4,030 bytes, +2 inputs (measured) | rejected. A fallback if the owner refuses a D11 node, accepting that blocked attempts without bytes go unrecorded. |
| (b) `Activity` properties (failed tool ids per run) | run-level only; no subject; no per-request detail | ≈ +1 KB | rejected |
| (c) one `Activity` per HTTP request | yes | lineage spine multiplied by every request; mixes operational granularity into the spine A1 keeps per run | rejected |
| (d) outside the graph (Mission Control receipts only) | Q-D11-17 from Mission Control, CQ-AX-04 not from the graph; Graph RAG agents could not tell "blocked" from "absent" | 0 | rejected for Q-D11-17 (value 1, harm) and K:CQ-AX-04 (value 2) |
| (e) pinned SourceDiscoveryRecord as-is (FOR_COVERAGE_REQUIREMENT, DISCOVERED_SOURCE edges, mutations, FOUND outcomes) | yes | 2 relationship types, 2 pairs, one record per discovery including successes | trimmed to (f) |
| **(f) `CaptureAttempt`, 0 relationship fields, written only for FAILED / PARTIAL requests** | **yes** | **+14,028 bytes, +4 inputs** (adversarial review; was +15,374 / +5 with the EMPTY_RESULT / CAPTURED outcomes and `ToolActionKind`) | **chosen** |

- Write rule (narrowed in the adversarial review): an attempt is written only when the outcome is FAILED or PARTIAL, i.e. only for non-captures that leave no kernel record. A successful capture is its SourceSnapshot. An authoritative "nothing" (a search with count 0, or a 404 for an id the source issues) is also a capture: its response is a COMPLETE SourceSnapshot and the statement is the kernel's FIELD_NOT_REPORTED Assertion (K `09` item 12). The model stage had an EMPTY_RESULT outcome pointing at that snapshot and an optional CAPTURED outcome; both duplicated kernel records and were dropped, with `resultCount` and the `ToolActionKind` enum (failureKind PARSE_ERROR / NO_TEXT_LAYER already names parse failures). Volume scales with failures, never with captures.
- Outcome and failure kind are two enums. The outcome (PARTIAL / FAILED) says whether bytes were kept (`snapshotUid` names a PARTIAL_EXCERPT snapshot); the failure kind (13 values, each observed on 2026-10-08) feeds readiness re-scoring and the G6 keys/quota decision.
- A FIELD_NOT_REPORTED is never turned into a NEGATIVE assertion about the world: PubMed `[si]` returned 0 for NCT02921659, yet the paper names the trial (FC-1). NEGATIVE is a denial (K item 12).
- Soft failures count as failures. A 200 response with an error or challenge page is FAILED with failureKind BOT_CHALLENGE; for example, Firecrawl's scrape of the CT.gov history tab returned "Error | ClinicalTrials.gov".
- Not `Subjectable`: nothing is asserted about an attempt, and keeping it off the interface keeps it out of every subject/object filter.
- Labels `["CaptureAttempt", "Entity"]`, the kernel directive for domain types (adversarial review; the model stage used `Occurrence` after the kernel's own `Activity`, which is a kernel type, not a domain precedent). The Occurrence archetype is stated in `06` and the label question is 11-open-questions item 40.
- Identity: uid = sha256(runId of the generating Activity | toolId | requestDigest | attemptedAt), enforced by the kernel uid uniqueness constraint (runId is not a property, so it cannot be a constraint key; `lastWriterRunId` equals it for an immutable attempt).
- Privacy: `requestUri`, `queryText` and `errorText` are stored only after the executor strips credential parameters (`api_key`, `key`, `token`, `email`). When a request names a person (an NPPES name search for Q-D11-16), the name is stored only as `sha256:<hex>` and `privacyClass` is INTERNAL (the kernel PrivacyClass has no stricter value; open question on API exposure).

### 3. Subject and response snapshot are uid properties, not edges

- `subjectUid` (indexed) answers CQ-AX-04 by property filter in both Cypher and GraphQL (`captureAttempts(where: {subjectUid: {eq: $uid}})`).
- An edge to `Subjectable` would cost ≈ 0 per implementer under the kernel pattern. It is still one more relationship type and pair, and it cannot represent an attempt for a subject that is not a node yet: a CAERS brand string, or a name searched before resolution. In that case only `queryText` exists.
- `snapshotUid` (set only for PARTIAL attempts whose bytes were kept) follows the kernel's own precedent for one-hop, non-traversed links (`revisesSnapshotUid`, `supersedesUid`, `reanchorsLocatorUid`). Both are listed under `deferred` in `05` with the condition that would promote them.
- Risk accepted: a uid property is not repointed when the subject is merged (risk 3).

### 4. Identifier schemes: accept the kernel's String register; D11 owns the bridges and normalization rules

- Research proposed a ~30-value `IdentifierScheme` enum. The kernel published `Identifier.scheme: String!` validated against `packets/K/identifier-schemes.yaml` (47 codes).
- Accepted: the register grows without a schema change, and an enum would put every new scheme on the synthesizer's desk.
- `identifier-bridges.yaml` now carries `kernelCode` per row. Four spellings were aligned to the kernel: EU_CT → EUCT, DSLD_LABEL_ID → DSLD, MESH_UI → MESH, CIK → SEC_CIK.
- Requested codes:
  - check stage: the K register v2 already carries five of them as `status: requested` (FDA_NDI, FDA_GRN, RW_RECORD, UDI_DI, NIH_PROJECT); D11 aligned its spellings (was NDI_NOTIFICATION, GRAS_NOTICE, RETRACTION_WATCH_ID, NIH_GRANT).
  - still missing from K, firm, each with a question: SPL_SET_ID (Q-D11-11), EIN (Q-D11-15), and ORG_STUDY_ID with issuer = sponsor.
  - cross-packet pass: also missing from K, from D12's node register: FNDDS_FOOD_CODE, NDB_NUMBER, FOODON, PHENOL_EXPLORER_FOOD, FOODEX2, LANGUAL, WWEIA_CATEGORY (`11-open-questions.md` item 46; generated `reconciliation` block in `identifier-bridges.yaml`, 114 codes).
  - optional, the owning domain decides: NCIT.
- No identifier-to-identifier edge exists or is proposed. A bridge is co-attachment of authority-asserted `HAS_IDENTIFIER` episodes on one entity, or an EQUIVALENCE / RESOLUTION Assessment. The table documents 22 bridges and 7 places where no bridge exists.

### 5. Selector vocabulary: accept the kernel's verification.v1 kinds

- Research preferred `SECTION` + `sectionScheme`. The kernel adopted verification.v1's 12 selector kinds plus WHOLE_SNAPSHOT, with the full selector as canonical `selectorJson`. JSON_POINTER and HTML exist as kinds, so the research question is settled.
- The registry's `locatorKinds` were remapped:
  - SECTION (JSON pointer) → JSON_POINTER
  - SECTION (element id) → HTML
  - PDF_PAGE → PDF_TEXT
  - IMAGE_REGION → BOUNDING_BOX
  - TEXT_POSITION → CHARACTER_POSITION
  - field name → API_RECORD
- Remaining gap: verification.v1 has no XML kind. JATS `sec@id`/`p@id` and SPL `section@ID` locators are written as HTML (DOM selector on the markup) until the verifier says otherwise (`11-open-questions.md`).
- TEXT_QUOTE needs the normalization version inside `selectorJson` to fold U+2009, U+00A0, U+202F and hyphen variants. FC-1's "500 mg" contains a thin space.

### 6. Integrity and revisions: reuse D3 `REVISES` and the kernel `revisionKind`

- Q-D11-04, Q-D11-05 and Q-D11-19 read D3 `REVISES` episodes, one per asserter. The kernel has `SourceSnapshot.revisionKind` / `revisesSnapshotUid` (pinned SourceRevisionEvent merged).
- D11 adds no integrity type. It does add gap G2 (an integrity checker that reconciles Crossref `updated-by` with PubMed CommentsCorrections), because discovery connectors drop both.

### 7. Text-mined annotations are never facts

- Europe PMC annotations go through a RESOLUTION Assessment that cites the span (`SourceLocator`, role CONTEXT; the kernel cut `Mention`) and the derived `MENTIONS` (method-versioned).
- Q-D11-10 lists the rejected ones. The observed mislink (NR tagged as ChEBI dihydrozeatin riboside) is the reason D11 does not propose an annotation node or edge.

### Cut list (06 deferred, 05 deferred)

- Edges: USED_TOOL/CAPTURED_WITH, ATTEMPTED_FOR, YIELDED_SNAPSHOT, SAME_AS/BRIDGES_TO, FOR_COVERAGE_REQUIREMENT, DISCOVERED_SOURCE, ANNOTATED_BY, RENDITION_OF_RECORD, REGISTERED_AS.

## Cross-packet pass: merged action space

The registry decision (decision 1) is unchanged; what changed is its scope. The schema module, the size estimate and the compile cost are untouched by this pass.

- Generated, not hand-merged. `_notes/action-space/build-action-space.mjs` reads every packet's `08` table and tool log, `05` populatedBy, `02` rows (value, polarity, sources) and `06` identifierSchemes, plus K's `identifier-schemes.yaml` v2. All judgment lives in `_notes/action-space/merge-spec.yaml`: 160 alias rules, 108 new canonical entries, 6 readiness overrides with reasons, 25 gap clusters and the scheme detection lists. A second run with `--check` reproduces the outputs byte for byte. Alternative: hand-merging 402 rows into one YAML. Rejected, because nobody could re-run it after a packet changes.
- Canonical ids. D11's 59 ids stay canonical, so the `toolId` / `captureMethod` vocabulary already used in D11 fixtures does not move. Every other packet-local id maps through the top-level `aliases` (`<packet>:<id as written>`). Result: 167 entries (144 external, 23 internal), 0 unmatched rows, 0 unresolved `populatedBy`.
- Readiness. Where packets disagree, the registry keeps D11's score for D11-local entries and the lower median elsewhere. The six exceptions are D11 overrides backed by evidence (item 51). Every packet's raw cell is kept in `seenAs`, so the adjudication can be audited.
- Priority. Packets use different scales (item 50), so priority is recomputed from the questions that need an entry and from its readiness, and it is never less urgent than D11's own score.
- Gap ranking. 3 points per value-1 question, 2 per value-2 and 1 per value-3, scoped to the packets that asked for the gap. "Blocked" means "needs an entry the gap serves". It is a build order, not proof that the gap alone blocks the answer (item 52).
- `access: internal`. 23 BellLabs-built writers and jobs (from K and D10) stay in the same registry on K's 0–3 build scale and are scored apart from external sources (item 49).
- What it does not do. Fixture `captureMethod` values are still free text in every packet. Until the kernel fixes `<registry id>/<version>` (item 45), the `captureMethod` → registry join (risk 7) holds only for D11's fixtures.

## Risks

1. **Attempt volume and noise.** An adapter that records every request, including successes, would multiply nodes. Mitigation: the write rule above (FAILED / PARTIAL only), enforced by the gap-G10 recorder.
2. **Credential leakage.** Request URIs carry keys (`api_key=DEMO_KEY` in this run; real keys in team runs). Mitigation: the executor strips credential parameters before hashing and storing, and the fixture checks it. This must be an executor test, not a convention.
3. **Dangling `subjectUid`.** When an entity is merged or superseded, the uid property is not repointed. Mitigation: CQ-AX-04 can widen the subject set to entities an accepted EQUIVALENCE Assessment ties to the subject. Promote to an `ATTEMPTED_FOR` edge if merges become common.
4. **"Not reported" read as absence.** An agent could turn "PubMed has no `[si]` link" (a FIELD_NOT_REPORTED) into "unpublished". Mitigation: the CQ-AX-04 pattern keeps NOT_REPORTED_BY_SOURCE apart from MEASURED_ABSENT and never emits a NEGATIVE assertion, and the fixture demonstrates exactly this trap.
5. **Sibling names drift.** D11's patterns read D3 `Publication` (contested with D9 `MediaWork`), D6 `LabelVersion`/`Package`, D8 `LegalStatus` and D9 index names. All are listed in `10-seams.yaml` so the synthesizer can re-point them.
6. **Tool renditions as evidence.** FC-2c, FC-7 and FC-9 are Firecrawl/Tavily markdown, not issuer bytes, and FC-7 lost a β. The kernel has no TOOL_RENDITION hash basis yet. Until it decides, assertions on renditions should stay below ACCEPTED.
7. **Config drift.** The registry is a file. If the tool layer and the registry disagree on ids, `captureMethod` joins break. Mitigation: registry ids are the only allowed `toolId` values (executor validation, G10). The registry is generated, so it is regenerated whenever a packet's `08` changes, and `--check` fails if the committed copy is stale. Sibling fixtures still write free-text `captureMethod` (item 45).
8. **A1 contests the node.** No longer open in substance: A1's model stage reads `CaptureAttempt` by `subjectUid` in its own CQ-AX-04 pattern (K `03`), lists the D11.CaptureAttempt → Activity WAS_GENERATED_BY seam in K `10-seams.yaml`, and records it as K open question 25 ("not a second lineage mechanism"). If the owner still refuses a D11 node, fall back to alternative (a), +4,030 bytes, and accept that no-bytes failures are only in Mission Control receipts. Since the review the node holds only what the kernel cannot (FAILED / PARTIAL requests), which narrows the disagreement to "blocked versus never queried" and Q-D11-17.

## With twice the budget

- An `ATTEMPTED_FOR` edge (CaptureAttempt → Subjectable), so GraphQL clients can nest coverage under any entity.
- A `ToolCapability` node carrying dated readiness history, so readiness trends are graph-queryable ("which sources degraded this quarter").
- A materialized per-tool reliability projection (failure rate by failureKind per week, method `tool-reliability/v1`) for the Mission Control planner.
- A `RegistryVersionDiff` derived node, so registry history (G1) becomes a first-class answer once enough self-observed snapshots exist.
- A licence/terms node per source, for the KEGG/LOINC/DrugBank decisions.

None of these is needed for a value-1 question today.
