Class definitions, as the script applies them:

- **kept**: the same name exists in v2.
- **merged**: a register row or ruling names a v2 type that absorbs this one.
- **renamed**: the only v1 type that maps to a v2 name v1 lacks.
- **removed:folded**: the type is gone. A packet's `mergedInto` sends it to a property, enum, predicate, config or "deferred".
- **removed:deferred**: a packet's `deferred` row cuts it.
- **demoted**: the relationship type survives as a registered predicate.
- **removed:pattern**: a deferral reason names the v2 relationship types that now carry the fact.
- **removed:unmapped**: no register row, ruling or reason names it.

The classes come from free-text register rows, so treat them as triage. The evidence column of every appendix row quotes the row the class came from.

**What the probe and the checks say, in one paragraph.** None of the 78 intents produce a usable plan under the current executor, and the current repo cannot build a workspace from v2. Against the v2 IR the unchanged planner rejects 63 intents and throws on 15. The two main causes are both in the planner:

- The SDL lever L2 (`@mutation(operations: [])`) makes **all 69 types non-creatable** for the executor: 791 TYPE_NOT_CREATABLE subject rejections.
- `mention.stage` asks for the removed `Mention` type.

With those two simulated away (and EXTRACTION mapped to INGESTION), the result is 1 applicable, 32 partial, 41 rejected and 4 thrown. That run also exposes the next layer: K's executor changes P1–P11 and P17, 20 v2 types without a uid token, and a planner crash on removed Assertion fields. `validateSidecars` reports 264 errors on v2 (0 on v1). Of the 1,151 statements in the pinned operations file, 561 name labels v2 does not have.

In the biotech-meta replay set:

- 3 of 257 Cypher files use only labels and relationship types that exist in v2 (a static check), and even those write v1 property and enum shapes. 3 are mostly lost, and 247 need remodeling.
- 4 of 25 GraphQL operations validate against the printed v2 API.

**Changes the probe found that K's list does not have:**

1. **Creatability from the register, not the SDL.** The planner rejects any subject whose SDL `@mutation` excludes CREATE (:356). v2 sets `@mutation(operations: [])` on all 69 types (lever L2, R-02), so 0 of 69 are creatable and 791 subject proposals fail TYPE_NOT_CREATABLE. R-03 already rules that the node register's `mutations` field is read as `{graphql: none, executor: […]}`. Carry `executor` into the IR (a sidecar or validation param) and test it instead of `allowedMutations`.
2. **uid tokens.** `schema.uidToken` (:363) reads the IR, whose `params.uidTypeTokens` come from the pinned `validation-params.json`: 190 tokens, 141 of them for types v2 lacks. 20 v2 types have none: Assessment, Association, Award, Brand, CaptureAttempt, DietaryPattern, FoodCategory, Frontier, Intervention, LabelVersion, LegalStatus, Lot, MediaWork, Package, Patent, QualityResult, RegulatoryRecord, Report, ReportItem, Taxon. 3. **Crash on removed Assertion fields.** `assertion.literal` does `assertion.properties.find((p) => p.name === k)!` for `quantityBasis`, `massBasis` and `amountReferent` (:777). v2 Assertion has none of them, so the planner throws a TypeError (4 intents, including `examples/ingestion-intent.example.json`).
