## Installer order (DDL phases)

1. pre-migration DDL (required.pre.cypher; enterprise.pre.cypher on Enterprise)
2. migration (S8 manifests, under KsWriteFence)
3. post-migration DDL (required.post.cypher; enterprise.post.cypher on Enterprise)
4. KsReleaseMarker (migrator, last)

Pre-migration: every statement that holds on a graph that still carries preserved legacy rows. Post-migration: constraints that cannot hold while legacy rows still carry the label or relationship type: uid_exists_<Label> for the legacy labels that are also stored v2 labels (legacy rows keep them until the migration relabels them to LegacyV0_<Label>) and the rel_<TYPE>_assertion_exists family (preserved legacy edges of a v2 type carry no assertionUid). Everything else is pre-migration.

Post-migration uid_exists labels (legacy rows carry them until relabeled): `Biomarker`, `Event`, `LabTest`, `Organization`, `Person`, `Product`, `Study`. Statement counts: {"pre-migration":502,"post-migration":69}.
