## Conventions (final SDL)

- **Current.** `recordedTo IS NULL` on a record or on an asserted edge episode; `EPISODE(r, $asOf)` as in the packet when an as-of answer is asked for.
- **Identifiers (R-42).** One (scheme, issuer, normalized value) identifies at most one Subjectable, and the executor enforces it. A pattern may find the one holder of an Identifier. It never joins two holders through one Identifier node.
- **Renditions (R-43).** A Source is grouped with its work by `(src:Source)-[:RENDITION_OF]->(work)`, where the work is a D3 Publication or a D9 MediaWork. The edge is asserted with recorded time only (`AssertedRecordedProperties`). It replaces the packet's "Sources join works through shared identifiers" rule.
- **Revisions (R-44).** An identified notice is D3 `REVISES` (`RevisionEdgeProperties`, `revisionKind` typed by K `SourceRevisionKind`, one episode per asserter). A status flag with no identified notice is a kernel `HAS_REVISION_STATUS` Assertion about a Source. Q-D11-04 and Q-D11-05 read both branches.
- **TRACE.** Written out as a scoped `CALL (a) { … }` subquery: Assertion → `HAS_EVIDENCE` → SourceLocator ← `HAS_LOCATOR` ← SourceSnapshot ← `HAS_SNAPSHOT` ← Source, with the asserter and the current `CAPTURE_FIDELITY` Adjudication. Inner variables are prefixed `t`. It aggregates, so a row with no evidence still returns, with an empty list.
- **Record kind.** Kind columns use `[l IN labels(x) WHERE l <> 'Entity'][0]`.

## Q-D11-05

*Which current assertions, assessments and reports rest on a rendition of a revised work, and since when does BellLabs know?* Kind: cypher.

- **Rulings: R-42, R-43, R-44.** The packet joined the revised Publication to its renditions through `(pub)-[:HAS_IDENTIFIER]->(id)<-[:HAS_IDENTIFIER]-(src:Source)`. Under R-42 the DOI or PMID Identifier belongs to the Publication only, so that join returns nothing. R-43 replaces it with RENDITION_OF. R-44 makes Q-D11-05 read both revision mechanisms.
- **What changed.**
  - The renditions are `(pub)<-[:RENDITION_OF]-(src:Source)` with the episode current.
  - The revision is filtered on the REVISES episode's own `revisionKind`, not on the notice's `publicationKind`. The packet's three notice kinds (RETRACTION_NOTICE, EXPRESSION_OF_CONCERN, CORRECTION_NOTICE) correspond to RETRACTION, EXPRESSION_OF_CONCERN and ERRATUM / CORRECTED_AND_REPUBLISHED. WITHDRAWAL is added, since it taints the work in the same way. `NEW_VERSION` (a preprint's journal version) does not taint and is left out. The notice's `publicationKind` is still returned.
  - A second branch reads the status flags (`HAS_REVISION_STATUS`, one per authority). A flag on one rendition taints every current rendition of the same work. A flag on a Source with no work taints that Source only.
  - The status, grouping and revision Assertions themselves are not listed as tainted.
  - Dependents use the non-`Entity` label.
- **How the question is answered now:** in full. Nothing is lost. `knownSince` is the REVISES episode's `recordedFrom` (the packet's meaning), or the flag Assertion's `recordedAt`.

```cypher
// @id Q-D11-05
CALL () {
  // R-44 branch 1: identified notice (D3 REVISES, per asserter); renditions through RENDITION_OF (R-43), never a shared Identifier (R-42)
  MATCH (notice:Publication)-[rv:REVISES]->(pub:Publication)<-[ro:RENDITION_OF]-(src:Source)
  WHERE rv.recordedTo IS NULL AND ro.recordedTo IS NULL
    AND rv.revisionKind IN ['RETRACTION', 'EXPRESSION_OF_CONCERN', 'ERRATUM', 'CORRECTED_AND_REPUBLISHED', 'WITHDRAWAL']
  RETURN pub.uid AS work, src, 'REVISES' AS mechanism, toString(rv.revisionKind) AS revisionKind, notice.uid AS notice,
         toString(notice.publicationKind) AS noticeKind, rv.assertionUid AS revisionRecord, rv.recordedFrom AS knownSince
  UNION
  // R-44 branch 2: status flag with no identified notice (kernel HAS_REVISION_STATUS, one per authority):
  // a flag on one rendition taints every current rendition of the same work
  MATCH (hs:Assertion {predicate: 'HAS_REVISION_STATUS'})-[:HAS_SUBJECT]->(flagged:Source)
  WHERE hs.recordedTo IS NULL
    AND hs.valueString IN ['RETRACTION', 'EXPRESSION_OF_CONCERN', 'ERRATUM', 'CORRECTED_AND_REPUBLISHED', 'WITHDRAWAL']
  OPTIONAL MATCH (flagged)-[fro:RENDITION_OF]->(pub:Publication) WHERE fro.recordedTo IS NULL
  OPTIONAL MATCH (pub)<-[sro:RENDITION_OF]-(sibling:Source) WHERE sro.recordedTo IS NULL
  WITH hs, pub, flagged, collect(DISTINCT sibling) AS siblings
  WITH hs, pub, siblings + [flagged] AS renditions
  UNWIND renditions AS src
  WITH DISTINCT hs, pub, src
  RETURN pub.uid AS work, src, 'HAS_REVISION_STATUS' AS mechanism, hs.valueString AS revisionKind, null AS notice,
         null AS noticeKind, hs.uid AS revisionRecord, hs.recordedAt AS knownSince
}
MATCH (src)-[:HAS_SNAPSHOT]->(:SourceSnapshot)-[:HAS_LOCATOR]->(:SourceLocator)<-[:HAS_EVIDENCE]-(a:Assertion)
WHERE a.recordedTo IS NULL AND NOT a.predicate IN ['HAS_REVISION_STATUS', 'RENDITION_OF', 'REVISES']
OPTIONAL MATCH (dep)-[:DERIVED_FROM]->{1,4}(a)                      // assessments, reports, calculated assertions
RETURN work, src.canonicalUri AS rendition, mechanism, revisionKind, notice, noticeKind, revisionRecord, knownSince,
       a.uid AS assertion, a.predicate AS predicate,
       collect(DISTINCT [l IN labels(dep) WHERE l <> 'Entity'][0] + ':' + dep.uid) AS dependents
ORDER BY knownSince DESC
```

## Q-D11-08

*For one study, line up the collaborator, material-provider, funder and competing-interest statements, and show where they disagree.* Kind: cypher.

- **Rulings: R-82** (with R-80 and R-15).
  - Funding of a Study is the typed `HAS_STUDY_ROLE {FUNDER}`. A paper-level funding statement is the D3 predicate `FUNDED_BY`.
  - A disclosure is one predicate, `DISCLOSES_INTEREST` (registered by D9). Its subject is the discloser or the work, and its object an Organization.
  - "No competing interest" is `DISCLOSES_INTEREST` with polarity `NEGATIVE` and speechAct `DENIES`.
  - D11 drops `DISCLOSES_SUPPORT_FROM` and `DECLARES_NO_COMPETING_INTEREST`.
- **What changed.**
  - The predicate list is now `HAS_STUDY_ROLE`, `FUNDED_BY` and `DISCLOSES_INTEREST`. An acknowledged material provider is `HAS_STUDY_ROLE {MATERIAL_PROVIDER}`, as the packet already said; `DISCLOSES_SUPPORT_FROM` had no other meaning.
  - A disclosure about an individual author has that author as subject (R-15, R-82). So the subjects now also include the authors of the reporting Publications, reached through current D3 `AUTHORED_BY` Assertions (R-80).
  - `REPORTS_ON` is read current.
  - The edge join `(st)-[role:HAS_STUDY_ROLE {assertionUid: a.uid}]->(org)` is kept.
  - New `statementKind` column. It names each row from its predicate, role kind, polarity and speech act: `COLLABORATOR`, `MATERIAL_PROVIDER`, `FUNDER`, `FUNDED_BY`, `DISCLOSES_INTEREST` or `DENIES_INTEREST`. A role kind not listed (such as `LEAD_SPONSOR`) falls through to the predicate name.
  - The `roleText:` qualifier (R-30) is returned as the verbatim role text.
  - The trace is a full TRACE subquery instead of a single required locator, so a statement with no captured locator still lines up.
- **How the question is answered now:** in full. Nothing is lost. The disagreement itself stays an Assessment (kernel CONFLICT_RELEVANCE, D7 subkind, R-55) if an analyst records it; the query only lines the statements up.

```cypher
// @id Q-D11-08
MATCH (st:Study)-[:HAS_IDENTIFIER]->(:Identifier {scheme: 'NCT', value: $nct})
OPTIONAL MATCH (pub:Publication)-[rep:REPORTS_ON]->(st) WHERE rep.recordedTo IS NULL
WITH st, collect(DISTINCT pub) AS pubs
// R-82 / R-15: an individual's disclosure has that author as subject; authors through D3 AUTHORED_BY (R-80)
CALL (pubs) {
  UNWIND pubs AS tp
  MATCH (au:Assertion {predicate: 'AUTHORED_BY'})-[:HAS_SUBJECT]->(tp)
  WHERE au.recordedTo IS NULL AND au.status <> 'REJECTED'
  MATCH (au)-[:HAS_OBJECT]->(author)
  RETURN collect(DISTINCT author) AS authors
}
UNWIND pubs + [st] + authors AS s
MATCH (a:Assertion)-[:HAS_SUBJECT]->(s)
WHERE a.predicate IN ['HAS_STUDY_ROLE', 'FUNDED_BY', 'DISCLOSES_INTEREST'] AND a.recordedTo IS NULL
OPTIONAL MATCH (a)-[:HAS_OBJECT]->(org)
OPTIONAL MATCH (st)-[role:HAS_STUDY_ROLE]->(org) WHERE role.assertionUid = a.uid
CALL (a) {
  OPTIONAL MATCH (a)-[tev:HAS_EVIDENCE]->(tloc:SourceLocator)<-[:HAS_LOCATOR]-(tsnap:SourceSnapshot)<-[:HAS_SNAPSHOT]-(tsrc:Source)
  OPTIONAL MATCH (a)-[:ASSERTED_BY]->(twho)
  OPTIONAL MATCH (tadj:Adjudication {adjudicationKind: 'CAPTURE_FIDELITY'})-[:ASSESSES]->(a) WHERE tadj.recordedTo IS NULL
  RETURN twho.uid AS asserter, [l IN labels(twho) WHERE l <> 'Entity'][0] AS asserterKind,
         collect(DISTINCT CASE WHEN tloc IS NULL THEN null ELSE
           {role: tev.role, selectorKind: tloc.selectorKind, selector: tloc.selectorJson, exact: tloc.exact, genre: tsrc.genre,
            contentHash: tsnap.contentHash, retrievedAt: tsnap.retrievedAt, uri: tsrc.canonicalUri, verdict: tadj.verdict} END) AS trace
}
RETURN [l IN labels(s) WHERE l <> 'Entity'][0] AS subjectKind, s.uid AS subject, a.uid AS statement, a.predicate AS predicate,
       CASE WHEN a.predicate = 'DISCLOSES_INTEREST' AND (a.polarity = 'NEGATIVE' OR a.speechAct = 'DENIES') THEN 'DENIES_INTEREST'
            WHEN a.predicate = 'HAS_STUDY_ROLE' AND role.roleKind IN ['COLLABORATOR', 'MATERIAL_PROVIDER', 'FUNDER'] THEN toString(role.roleKind)
            ELSE a.predicate END AS statementKind,
       role.roleKind AS roleKind, a.polarity AS polarity, a.speechAct AS speechAct, org.uid AS organizationUid, org.name AS organization,
       [q IN a.qualifiers WHERE q STARTS WITH 'roleText:' | trim(substring(q, 9))][0] AS roleText, a.valueString AS statedText,
       asserter, asserterKind, trace
ORDER BY organization
```

- trace: TRACE per statement (FC-1: ack "Study pills, NR standards for metabolite analyses and partial funding support were provided by ChromaDex, Inc." as MATERIAL_PROVIDER and FUNDER, both asserted by the Publication; notes "The authors declare no competing interests." as DENIES_INTEREST with no object; FC-8: CT.gov collaborator "ChromaDex, Inc." asserted by the sponsor).

## Q-D11-19

*For a preprint, which journal version revises it, and how does the wording of each shared claim differ between the two versions?* Kind: cypher.

- **Rulings: R-42, R-43.** The packet reached the captured renditions of the preprint and of the journal article through `(pub)-[:HAS_IDENTIFIER]->(:Identifier)<-[:HAS_IDENTIFIER]-(src:Source)`, two shared-Identifier joins. Under R-42 those Identifiers belong to the Publications only. R-43 replaces the joins with RENDITION_OF.
- **What changed.**
  - Both joins now read `(src:Source)-[:RENDITION_OF]->(pub)` with the episode current. The journal side is an `EXISTS` subquery on `jSrc`.
  - The lookup of the preprint by DOI is unchanged. It finds the one holder of that Identifier, which R-42 allows.
  - The preprint's renditions are now optional, so a preprint with a REVISES row but no captured rendition still returns that row. This is the packet's "no published version known" case read the other way.
  - The REVISES episode's `revisionKind` and authorizing Assertion are returned, and only current occurrences are compared.
- **How the question is answered now:** in full. Nothing is lost.

// @id Q-D11-19
MATCH (pre:Publication)-[:HAS_IDENTIFIER]->(:Identifier {scheme: 'DOI', value: $preprintDoi})   // the one holder of the DOI (R-42)
OPTIONAL MATCH (jrnl:Publication)-[rv:REVISES]->(pre) WHERE rv.recordedTo IS NULL
OPTIONAL MATCH (pre)<-[pro:RENDITION_OF]-(preSrc:Source) WHERE pro.recordedTo IS NULL       // R-43, not a shared Identifier
OPTIONAL MATCH (occ:Assertion {assertionKind: 'CLAIM'})-[:HAS_EVIDENCE]->(:SourceLocator)<-[:HAS_LOCATOR]-(:SourceSnapshot)<-[:HAS_SNAPSHOT]-(preSrc)

OPTIONAL MATCH (occ)-[:OCCURRENCE_OF]->(claim:Claim)

## CQ-PV-05

*Which captured Sources render the same record, which is the issuer's endpoint and which an aggregator, and how stale is each?* Kind: cypher (+ CONFIG).

- **Rulings: R-42, R-43.** The packet found the renditions of one record as "two Sources that share an identifier (NCT, SPL_SET_ID, DOI)". Under R-42 one (scheme, issuer, value) identifies at most one Subjectable, so two Sources can no longer hold the same Identifier node. Its holder is the record itself: a D3 Publication for a DOI, a D3 Study for an NCT, a D6 LabelVersion for an SPL_SET_ID. R-43 gives a typed rendition grouping only for Publications and MediaWorks.
- **What changed.**
  - The record is found as the holder of the Identifier (current `HAS_IDENTIFIER` episode); several issuers of one value give several holders. The renditions of the record are read two ways and labeled by `groupings`:
    - `RENDITION_OF`: Sources with a current `RENDITION_OF` edge to the holder (Publication or MediaWork; R-43).
    - `EVIDENCE_OF_ASSERTIONS`: Sources whose captures are the evidence of current assertions about the holder. This is how a CT.gov record and its ICTRP copy (holder: the Study), or a DailyMed SPL and its openFDA copy (holder: the LabelVersion), are grouped in the final SDL, which has no typed rendition edge for them.
    - `IDENTIFIER_HOLDER`: when the holder is itself a Source (an endpoint identifier), that Source.
  - Freshness is unchanged: the latest capture time per Source and the Source's own current `RECORD_LAST_UPDATED` Assertion (kernel literal, registered). The tool ids now come from every capture method, not just the first one collected.
  - The primary-vs-aggregator call stays a client join on the tool id (CONFIG `tooling/action-space.yaml`).
- **How the question is answered now:** in full for scholarly records. For registry records and drug labels it is answered through the evidence grouping. That grouping finds a rendition only after some assertion about the record cites it, so a captured copy that nothing cites yet is not listed. A typed rendition grouping for drug labels and registry records needs an owner or K ruling, and the SDL is not changed in this round. The item is carried as the D11 SPL_SET_ID shared-identifier row of FU-03 and is restated in FU-14.

```cypher
// @id CQ-PV-05
// the holder of the record identifier (R-42: one holder per (scheme, issuer, value); several issuers give several holders)
MATCH (holder)-[hl:HAS_IDENTIFIER]->(:Identifier {scheme: $scheme, value: $value})
WHERE hl.recordedTo IS NULL
CALL (holder) {
  // R-43: the typed rendition grouping (Publication or MediaWork)
  MATCH (src:Source)-[ro:RENDITION_OF]->(holder) WHERE ro.recordedTo IS NULL
  RETURN src, 'RENDITION_OF' AS grouping
  UNION
  // no typed grouping for registry records (Study) and drug labels (LabelVersion): the Sources that evidence current assertions about the holder
  MATCH (holder)<-[:HAS_SUBJECT]-(ha:Assertion)-[:HAS_EVIDENCE]->(:SourceLocator)<-[:HAS_LOCATOR]-(:SourceSnapshot)<-[:HAS_SNAPSHOT]-(src:Source)
  WHERE ha.recordedTo IS NULL
  RETURN src, 'EVIDENCE_OF_ASSERTIONS' AS grouping
  UNION
  // an endpoint identifier held by a Source itself
  MATCH (src:Source) WHERE src = holder
  RETURN src, 'IDENTIFIER_HOLDER' AS grouping
}
WITH holder, src, collect(DISTINCT grouping) AS groupings
MATCH (src)-[:HAS_SNAPSHOT]->(snap:SourceSnapshot)
OPTIONAL MATCH (fresh:Assertion {predicate: 'RECORD_LAST_UPDATED'})-[:HAS_SUBJECT]->(src) WHERE fresh.recordedTo IS NULL
WITH holder, src, groupings, max(snap.retrievedAt) AS lastRetrieved, max(fresh.valueString) AS lastUpdatedPerSource,
     collect(DISTINCT fresh.uid) AS freshnessRecords,
     [m IN collect(DISTINCT snap.captureMethod) WHERE m IS NOT NULL | split(m, '/')[0]] AS toolIds
RETURN [l IN labels(holder) WHERE l <> 'Entity'][0] AS recordKind, holder.uid AS record, src.canonicalUri AS rendition, src.genre AS genre,
       groupings, toolIds, lastRetrieved, lastUpdatedPerSource, freshnessRecords
ORDER BY record, lastUpdatedPerSource DESC
// client side: JOIN toolIds -> CONFIG registry (primary vs aggregator); lag = primary.lastUpdated - aggregator.lastUpdated
```

- EXPLAIN: ok on Neo4j 5.26.31 community (1/1 statement); final-SDL static check clean (labels, types, pairs, properties, enum values, predicates)
- trace: TRACE of each `RECORD_LAST_UPDATED` Assertion (`freshnessRecords`; FC-8: ICTRP HTML `span#DataList3_ctl01_Last_updatedLabel` "12 December 2016" vs CT.gov `/protocolSection/statusModule/lastUpdatePostDateStruct`; FC-3: openFDA flattens the SPL boxed-warning section and loses its id), and of the assertions that put each Source in the `EVIDENCE_OF_ASSERTIONS` group.
- fixture: `final/fixtures/D11/sirolimus-spl-boxed-warning` (i01 SPL_SET_ID on the LabelVersion; i02 still attaches the same value to the openFDA Source, owner-gated under R-42, FU-03), `final/fixtures/D11/nr-trial-jats-unstructured` (CT.gov and PubMed captures of NCT02921659).
- bitemporal episode needed on: kernel `HAS_IDENTIFIER` (an episode already; a rendition endpoint can be re-pointed) and `RENDITION_OF` (recorded time only).
